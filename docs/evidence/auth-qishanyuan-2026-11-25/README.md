## 在测试包中查看

`miniprogram/config/runtime.js`显式设置`testPropertyPreset:'qishanyuan-test-v1'`。此开关只选择随包提供的测试房源，不改变live运行模式，也不允许把云接口失败回退成演示成功。去掉该开关即恢复现有云房源调用；本次没有向线上数据库导入242间房。

在项目根目录运行`npm run admin:qishanyuan`，会创建专用`admin-web/.data/qishanyuan-test-v1`，只能本机访问demo后台。该实例初始包含242间rooms、物业目录和空houses；不会自动把待定价格数据发布为租赁houses，也不会覆盖旧`.data/demo`或live数据。未知、半初始化、标记不符的专用目录会拒绝覆盖；认可的重启保留管理员修改，不重置账户和审计。

此命令是交付后的本机操作说明。本轮只使用临时目录测试初始化，没有启动实际后台监听。后台导航“栖山苑测试基准”展示只读基准；“房源管理”编辑的是本地隔离实例，修改不会自动改写随包静态基准或生产云。

## 管理员开通账号密码

保留手机号快捷登录。住户在“我的→账号密码登录”生成有效10分钟的一次性开通码，将码交给管理员核对本人。管理员登录管理后台后进入“租客账号密码”，用开通码、用户名和初始密码创建账号；住户再以同一微信身份使用账号密码登录。

- 用户名：4–32位，字母/数字开头，只包含字母、数字、`.`、`_`、`-`；服务端统一去首尾空格并转小写。
- 密码：8–128字符，UTF-8不超过256字节，原文参与校验，不trim或改大小写。无随包默认账号、默认密码或内置真实凭据。
- 服务端保存独立随机盐的scrypt-v1哈希；不向列表、日志、用户资料、开通回执或审计输出明文密码、盐或哈希。客户端密码只作当前提交，在提交、离页和完成时清空，不进入缓存、URL或剪贴板。
- APPID/OPENID只读云平台可信上下文，客户端不能选userId/openid。密码账号与同一微信身份、同一users记录绑定，换微信不能凭密码接管旧房屋权限。历史重复users不自动合并或取第一条。
- 旧手机号/微信登录共同使用确定性身份协调器；保留同一用户和管理员维护的housesManaged绑定。
- 开通码消费、账号创建/重置/启停和内部审计使用真实数据库事务。登录的持久额度在KDF前占用；KDF后事务复核账号revision、密码版本和当前启停状态，防止重置或停用期间旧结果通过。
- “停用”仅停用密码入口；没有引入全局会话撤销，也不声称禁用微信/手机号登录或撤销原有房产权限。后台管理员凭据仍与租客凭据分开。

## 云端部署前置（本轮未执行）

账号密码使用新增`accountLogin`及同版`login/phoneLogin/adminLogin`的函数本地身份模块。四份`identity-core.js`由来源校验器逐字节核对，不能只更新其中一个函数或依赖兄弟函数目录。

部署者须先按accountLogin目录说明创建私有集合和访问规则：五个`tenant_auth_*`集合禁止客户端SDK直接读写；users中的身份索引、role、houses及管理员绑定由可信服务端管理。权限规则、索引、SDK事务行为和函数部署均需要在独立测试云环境核验。本轮未部署规则、云函数或小程序，没有扫码登录或访问真实设备。

打包命令为`npm run release:checkin-face`，产物是包含小程序、云函数、后台及离线测试的源码ZIP，不是微信平台wxapkg。包内仍保持`allowDeviceOperations:false`；体验版上传、账号开通的真实云验证及现场刷脸需另行执行并记录，不能将合成测试当作平台或设备通过。

原246项输入P2验收、EOF NOT_COVERED及其历史证据不重开；原旧版本ZIP保留。本轮不改变合同、退款或租期业务政策，不自动填测试租期。
