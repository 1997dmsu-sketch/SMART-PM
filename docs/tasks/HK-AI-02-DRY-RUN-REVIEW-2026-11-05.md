## 真实执行前代码复审补充

再次审查 `f90f199` 后，离线测试与 dry-run 结论保持通过，但真实设备执行仍有以下阻断项：

1. `runProbe()` 没有接收或校验预批准的完整型号。读取 `deviceInfo` 后即继续后五个 GET，无法落实“型号不符立即停止”。新增只从受控环境读取的 `HIKVISION_PROBE_EXPECTED_MODEL`，要求与解析出的完整型号精确匹配；缺失、解析为空或不一致均在第二个请求前 fail closed。
2. 编排器把认证失败、指纹错误、重定向、超时、响应超限和内容类型异常仅记为单端点失败，随后继续请求其余端点；这与现场清单的立即停止条件不符。正常的首次 401 Digest challenge 可重试一次，第二次 401、不可解析 challenge 及上述安全/传输错误必须中止余下请求。
3. README 的现场命令把用户名和密码以内联 `export` 示例展示，可能进入 shell history；改为受控秘密注入或无回显读取示例，并在结束后显式清除。当前试点固定使用指纹模式，README 不应再写“自签名设备必须提供 CA”，且现场示例必须包含指纹而不能默认系统信任链。
4. `HIKVISION_PROBE_OUT_DIR` 指向既有目录时，`mkdir(..., mode:0700)` 不会收紧旧权限；应显式校验/设置目录 `0700`，并以 `0600` 写入脱敏 `report.json`。任何权限设置失败都应停止，不能继续落盘。
5. 完成说明和 README 的测试数量仍写 44/45，与实际 46 不一致；修正文档和矩阵计数。
