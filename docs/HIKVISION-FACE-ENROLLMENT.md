# DS-K1T671BM 人脸联调

本功能位于电脑管理端的“人脸门禁”，用于单名已同意参与测试的人员。它独立于旧 probe CLI，不修改旧 `allowRead`、离线桥或历史证据。当前交付为本地联调功能，尚未完成真实人员、真实照片及现场刷脸验收。

## 本机使用

1. 在本分支运行 `node admin-web/server.mjs`，默认本地演示服务为 `http://127.0.0.1:4173`，进入演示工作台。
2. 点击“人脸门禁”，默认模拟模式；点击“连接模拟设备”后填写合成编号、显示名、有效期并选择 JPEG，即可验证四阶段流程。模拟结果不会下发设备。
3. 真实联调须切换“现场设备”，在本机表单输入 HTTPS 地址、设备管理员凭据，选择已另行核验的公开服务器证书。证书文件只用于提取公钥 pin，不导入系统根证书。连接先读取设备信息、人员能力、人脸能力和库列表；编号、库和门由返回能力约束。
4. 严格 TLS 默认开启。已获授权的开发联调可显式选用开发证书模式：仅当前连接允许链/名称例外，仍强制校验证书公钥，匹配前不发送 HTTP。首次观察到的证书不自动构成可信身份。此模式不代表生产 TLS 验收通过。
5. 使用全新的测试人员编号、获得本人同意的正面 JPEG、明确的测试有效期和门号。点击“同步人员和人脸”会实际建人、上传生物识别照片并授予所选门权限，可能使该人员在有效期内刷脸开门。现场必须先确认人员、照片、门号和有效期。

页面按比例生成最长边不超过 960 像素的 JPEG，不裁剪；超过大小时继续调整质量及尺寸。200 KiB 是本次按接入指南设置的工作上限，并非设备能力返回的字节上限。图片压缩不保证人脸质量、活体能力、建模成功或识别成功。

有效期默认“固定期限”。仅当设备人员能力明确允许 `Valid.enable=false` 时才开放“长期有效”；此时不要求操作者填写日期，后台仍从能力范围产生协议必需的合法 `beginTime/endTime`，以布尔 `enable:false` 表示长期。界面仅显示“长期有效”，不会把有限截止日期写作永久。查询及不确定结果重试都核对相同的 enable、日期和本地时间模式，设备读回相反模式时停止确认。实际设备是否接受并正确读回此模式仍需首次真实下发验证，离线记录见 [长期有效验证](evidence/hk-face-enrollment/UNLIMITED-2026-11-24.md)。

## 四阶段与状态

| 阶段 | 请求与行为 |
| --- | --- |
| 建人 | 查询指定编号，已有编号停止而不覆盖；新建普通人员，设定本地时间有效期，显式空 `doorRight`，不提前授门权。 |
| 上传人脸 | `PUT /ISAPI/Intelligent/FDLib/FDSetUp?format=json`；multipart JSON part `faceURL`、JPEG part `img`，`FPID=employeeNo`；成功响应后才标记已提交。 |
| 授权门 | `PUT /ISAPI/AccessControl/UserInfo/Modify?format=json`，仅授予所选 `doorRight`，受人员有效期约束。 |
| 查询确认 | 查询人员、姓名、有效期和门权。明确支持 FDSearch 时核对目标 FPID 的 `isInLibrary=yes`；不支持时仅核对 `numOfFace>0`，不调用 FDSearch。 |

`ready` 表示接口查询确认，包括支持时的建模确认，仍待现场刷脸。`pending-site` 表示本次上传已获成功响应、人员/门权/人脸关联数量已确认，但设备不支持建模查询；界面显示“已下发，待现场刷脸”。关联数量不能证明当前库建模完成。两者均不代表现场门锁已被该人脸释放。

失败保留阶段与错误，不自动重试、回滚、删除人员或撤销权限。超时可能已在设备生效，查询不会把上传尝试当作成功提交；须由操作者检查再显式继续。继续同步只跳过已完成阶段，人员创建结果不明时先查询并比对本次记录。它不是跨客户端、跨进程的原子事务，也不能排除外部管理员同时修改设备的竞争；首次仅使用独占的新测试编号，避免并发设备管理。页面关闭、进程重启或断开后不保证续传。

本次实测固件返回 `isSuportFDSearch=false`，因此真正的建模/识别结论只能通过后续获准的现场刷脸及相应事件核对取得。

## 数据与访问边界

- 接口仅允许本机 loopback 的已登录管理端管理员；沿用会话、Origin 和 CSRF 检查。按会话 token 隔离设备客户端及记录。
- 凭据、证书配置、照片只保存在当前进程/页面内存，不写公共上传目录、业务 store、云数据库或业务日志。状态 DTO 不含照片和凭据；未对内存副本作不可恢复擦除承诺。
- 服务端照片缓冲区成功后释放；失败时最多保留十分钟，断开/退出/会话失效也关闭客户端并释放。浏览器失败重试照片在当前页面内存，离开页面或断开后释放引用。
- 仅初次 HTTP 401 允许一次 Digest 认证重发；不跟随重定向，超时与断链不自动重发写入。错误公钥或缺失证书时不发送 HTTP。
- 这是本地管理员开发工具，不是对公网发布的任意设备代理。保持默认 loopback 监听；不新增云访问、设备开门按钮、批量导入、删除或生产部署。

## 本地 API 与检查

新增 `GET /api/face/state` 和 `POST /api/face/connect`、`disconnect`、`enroll`、`retry`、`verify`。所有 POST 均沿用管理端 CSRF/Origin；`enroll` 需要 `consent:true`。只接受界面/能力所限定的人员、门和库；照片请求体上限 1 MiB，照片本身上限 200 KiB。

无需安装新依赖即可运行：

```sh
npm --prefix admin-web test
```

测试使用合成 TLS 证书、假设备和合成 JPEG 字节，不发送真实设备写入。测试夹具中的私钥专用于合成 loopback TLS 测试，不是设备密钥。实现和实测范围见 [本轮报告](evidence/hk-face-enrollment/IMPLEMENTATION-2026-11-24.md)。
