## P0-1：幂等键未按组织、路由和 actor 隔离

当前 `operations` 只以裸 `context.idempotencyKey` 为 Map key，摘要也只包含 input。独立复现：org/actor 均不同的两个 context 使用相同 key 和 input，第二次重放第一个 job，`calls.length=1`。

修复：operation identity 必须包含 `orgId + route/method + actorType + actorId + idempotencyKey`；requestDigest 的规范化域至少包含 actorType 与业务输入。补充同 key 下跨 org、跨 actorId、跨 actorType、跨方法均互不重放的测试；同一完整作用域同 key 同输入才重放。

## P0-2：设备证据来源条件使用错误布尔逻辑

当前判断为：

```text
source != device && kind != device_ack 才拒绝
```

这会允许只满足其中一个条件的伪造证据。独立复现中 `source=device`、`kind=wrong_kind` 仍得到 `deviceEffective=true`。

修复：`source=device` 与 `kind=device_ack` 必须同时成立，任一不符即拒绝；并继续要求 trusted、device_verified 及 org/device/grant/job/action 全匹配。分别增加“正确 source + 错 kind”和“错 source + 正确 kind”用例。

## P0-3：事件没有绑定设备、组织及递增版本

job 记录未保存 org/device/grant，`verifyEvent` 只按 jobId 查找，不核对 event.deviceId 或 context.orgId；version 只验证为正整数，没有维护目标 job/device 的最高版本。独立复现：错误 deviceId 的版本2事件被匹配，随后版本1也被接受。

修复：Mock job 保存 orgId/deviceId/grantId/credentialId；事件必须与 job 和 context 组织一致。按目标 job/device 保存最高版本：同 eventId 同摘要可重放；新 eventId 的版本必须严格递增；旧版、乱序、错误设备、跨组织均 rejected/CONFLICT 且不推进任务。未知 job 返回 `{rejected:true}`，不得填写 `matchedJobId`。
