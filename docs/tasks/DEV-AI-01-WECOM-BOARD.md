# DEV-AI-01：企业微信开发看板同步 MVP

优先级：P1  
执行者：Workburry  
复审者：Codex  
建议分支：`feat/wecom-dev-board`  
基准：`docs/lock-01-fast-track@1358ef5`  
状态：已分配，可立即开始

## 目标

把仓库内任务卡和明确的认领状态汇总为适合企业微信查看的开发看板，并支持每天 **18:00（Asia/Shanghai）** 生成日报消息。第一阶段使用 fixture/Mock 完成全流程，不发送到真实企业微信。

## MVP 范围

1. 从仓库内受控数据源读取任务：`docs/tasks/*.md` 和一份新增的机器可读看板清单；不得依赖自然语言猜测提交是否完成。
2. 展示字段：任务编号、标题、执行者、状态、优先级、依赖、分支、最后更新、阻碍、复审人及 GitHub 链接。
3. 看板分栏固定为：待认领、进行中、待复审、阻塞、已完成。
4. 提供桌面与企业微信内置浏览器可用的只读响应式页面；首屏优先显示 P0/P1、阻碍和待复审任务。
5. 生成企业微信 Markdown/文本消息预览，内容包括今日完成、进行中、阻碍、明日计划、待真人处理。
6. 提供企业微信发送适配层：默认 `mock`，真实模式只接受运行环境中的 webhook/应用凭据，代码、日志、页面和测试不得保存或返回凭据。
7. 提供幂等键 `reportDate + boardVersion + destinationIdHash`，避免同一日报重复发送。
8. 提供手动“生成预览”与定时任务入口；定时表达式和时区显式配置，默认每天 18:00、`Asia/Shanghai`。

机器可读清单只保存任务状态及 GitHub 引用，不复制设备资料、身份资料或人脸数据。Markdown 任务卡仍是人类说明，清单是看板唯一状态源；两者不一致时报告错误，不静默猜测。

## 企业微信接入边界

- 优先实现群机器人 webhook 适配器；若企业微信限制无法满足，再单独评估自建应用，不在本任务擅自扩大权限。
- 默认只生成预览；只有显式设置 `WECOM_BOARD_SEND=true` 才允许调用发送适配器。
- webhook URL、CorpID、Secret、AccessToken、群 ID、用户手机号和 OpenID 均不得进入 Git、页面、测试 fixture 或错误日志。
- 禁止发送原始 ISAPI 文档、设备地址/序列号、密码、人脸、证件、手机号及其他私密数据。
- HTTP 请求必须有超时、响应体上限和目标域名白名单；不得跟随跨域重定向。
- 发送失败只记录脱敏错误和可重试状态；不得无限重试。真实发送、收件群选择和定时任务启用由项目负责人配置后另行验收。

## 验收测试

1. 缺少真实凭据时，完整生成页面和消息预览且网络调用为 0。
2. 状态、优先级、依赖和 GitHub 链接渲染正确；未知状态和缺少任务编号直接报错。
3. P0/P1 阻碍不会因截断而从日报消失；普通已完成项可折叠。
4. 消息超过企业微信单条限制时确定性分片，分片均带日期和序号。
5. 同一幂等键只发送一次；失败重试有上限，测试不等待真实时间。
6. 日志和异常中不出现 webhook、token 或 fixture 中的哨兵秘密。
7. 页面在 375px、430px 和桌面宽度下可读，无横向溢出。

## 不在本任务范围

- 修改海康门禁、数据库、人脸文件或管理后台业务代码。
- 自动判断 PR 已合并、自动修改任务状态或向 GitHub 回写。
- 真实企业微信发送、创建企业微信应用、邀请成员或配置生产定时器。
- 审批流、聊天机器人问答和企业微信通讯录同步。
