## 3. AI 任务卡

### HK-ISAPI-AI-01：文档证据矩阵

负责人：文档证据 AI  
分支：`docs/hk-isapi-evidence`

任务：

1. 从两份指南建立型号适用表，明确 `DS-K1T671B`、`DS-K1T671BM-3XFTD` 与现场设备的差异。
2. 整理人员、人脸、权限计划、门、事件、查询、删除、认证、容量和错误码接口。
3. 每条结论记录文档包、章节、页码/文本位置、接口、能力节点和适用条件。
4. 从 `错误码.xlsx` 提取本项目实际可能使用的错误码子集；没有接口上下文的错误码不得直接映射可重试性。
5. 建立“文档存在 / 目标设备 capability 支持 / 真实调用验证”三级证据列。

验收：任何 Provider 端点都能追溯到文档和 capability；不能用近似型号替代现场证据。

### HK-ISAPI-AI-02：只读设备能力探针

负责人：探针开发 AI  
分支：`feat/hk-isapi-capability-probe`

允许访问的首批只读接口：

```text
GET /ISAPI/System/deviceInfo
GET /ISAPI/AccessControl/capabilities
GET /ISAPI/AccessControl/UserInfo/capabilities?format=json
GET /ISAPI/Intelligent/FDLib/capabilities?format=json
GET /ISAPI/Intelligent/FDLib?format=json
GET /ISAPI/Intelligent/FDLib/Count?format=json
```

任务：

1. 实现 HTTPS + Digest 客户端，连接信息只从运行环境读取。
2. 默认 `dry-run`，显式 `HIKVISION_PROBE_ALLOW_READ=true` 才允许只读请求。
3. 禁止跟随到非白名单主机；限制端口、路径、超时和响应大小。
4. 输出结构化报告：HTTP 状态、ISAPI 状态、能力节点、设备型号、固件、容量和响应摘要。
5. 报告自动脱敏 IP、序列号、MAC、用户名、realm、nonce、cookie、证书主体和设备唯一标识。
6. 原始响应只保存在受控临时目录，不提交 Git；提交经过审查的脱敏 fixture。
7. 本任务不得实现 POST/PUT/DELETE，不得新增测试人员或人脸。

验收：无凭据、错误主机、证书异常、超时和 capability 缺失均安全失败；日志不泄露凭据或设备标识。

### HK-ISAPI-AI-03：ISAPI 路线与安全边界冻结

负责人：架构/安全 AI  
分支：`docs/hk-isapi-route-decision`

任务：

1. 根据只读探针判断设备侧 ISAPI 是否满足人员、人脸、查询和删除闭环。
2. 确定云端不能直达设备时的边缘代理拓扑。
3. 只允许服务端/边缘代理访问设备，小程序和浏览器不能直连。
4. 定义设备账号最小权限、凭证轮换、证书校验、设备白名单、命令白名单和紧急停用。
5. 冻结首发 Provider 接口白名单；明确禁止“删除全部人脸库”。
6. 给出发送前失败、发送后未知、查询对账和人工复核的状态映射。

验收：形成批准/拒绝进入真实 Provider 开发的明确结论；拒绝时列出缺少的 capability。

### HK-ISAPI-AI-04：离线响应夹具与契约测试

负责人：测试 AI  
分支：`test/hk-isapi-contract-fixtures`

任务：

1. 使用脱敏响应建立设备信息、人员 capability、人脸 capability、人脸库和数量 fixture。
2. 覆盖支持/不支持、空库、容量不足、认证失败、HTTP 错误、ISAPI 错误和畸形响应。
3. 覆盖近似型号但 capability 不支持时拒绝进入真实写流程。
4. fixture 不含 IP、序列号、MAC、用户名、realm、nonce 或真实人脸信息。

## 4. 项目负责人真人任务

### HK-ISAPI-HUMAN-01：现场设备身份确认（您负责）

请完成并提交给开发 AI：

1. 拍摄设备背面/侧面铭牌，确保完整型号后缀清晰。
2. 在设备管理页面记录：设备型号、固件版本、构建日期、硬件版本。
3. 确认是否为测温型号，是否带 `-3XF/-3XFTD` 等后缀。
4. 记录设备当前是否已投入真实门禁使用；优先提供未承载生产通行的测试机。
5. 联系海康支持，书面确认该完整型号/固件适用哪一份 ISAPI 指南。

隐私要求：发给 AI 前遮盖完整序列号、MAC、激活码、二维码、IP、账号和密码；只保留末 4 位用于人工区分。

### HK-ISAPI-HUMAN-02：隔离测试网络准备（现场网络人员）

1. 将测试设备放入独立 VLAN 或隔离局域网，不把管理端口直接映射公网。
2. 准备一台同网段边缘测试主机，用于执行只读探针。
3. 给设备分配固定局域网地址，并限制只允许边缘主机访问。
4. 确认 HTTPS 端口、设备时间/NTP和证书状态。
5. 建立随时断网和恢复出厂/清理的现场操作能力。

不得把设备管理员密码发到聊天或 GitHub；由现场人员在受控运行环境中配置。

### HK-ISAPI-HUMAN-03：厂商确认（海康支持联系人）

需要海康书面答复：

1. `DS-K1T671BM` 是否等同/归属指南中的 `DS-K1T671B`，还是存在完整后缀。
2. 目标固件是否支持 UserInfo、FDLib、人脸新增/查询/修改/删除。
3. 是否需要额外许可、SDK、HikCentral 或合作伙伴权限。
4. 推荐固件及已知兼容问题。
5. 人脸图片格式、大小、分辨率、质量、容量和下发频率。
6. 删除人员是否同步删除人脸，以及如何确认无残留。

### HK-ISAPI-HUMAN-04：测试人员与清理签字（您或运营负责人）

1. 指定 1 名内部测试人员并取得书面测试同意。
2. 指定 1 扇测试门和可随时人工开门的备用方案。
3. 现场确认录入后能识别、撤销后不能识别。
4. 联调结束核对设备人员列表、人脸库和权限列表均无测试残留。
5. 在联调报告中签字确认测试范围、时间和清理结果。

## 6. P0 阻碍

1. 现场完整型号不明，现有两份指南都未精确列出裸型号 `DS-K1T671BM`。
2. 目标固件 capability 尚未读取。
3. 测试设备和边缘主机未准备。
4. 设备管理账号、HTTPS 和网络可达性未确认。
5. 厂商尚未确认指南适用范围、许可和推荐固件。

这五项关闭之前，只能开发只读探针和离线契约，不能向设备下发真实人员或人脸。
