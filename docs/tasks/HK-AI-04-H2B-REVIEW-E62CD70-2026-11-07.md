测试全绿，但 helper 与已冻结设计存在以下阻断。

## P0-1：错误引入 K1 fingerprint

`digestDomainMatchesDevice()` 要求 head/version 均含 64 位 `keyFingerprint`，测试 fixture 也伪造了 fingerprint。当前 `device_digest_domains` schema 没有该字段，编码卡明确禁止新增或依赖 K1 fingerprint。

### 修复

- 删除 `HEX64` 和 K1 fingerprint 校验/fixture；
- 对 head/version 分别复用 `validateDigestDomainRecord()`；
- 缺失、kind 错、字段缺失、head/version 内部矛盾返回 `DOMAIN_INCOMPLETE`；
- 两条记录自身完整但与 device 的 provider/realm/keyVersion 不一致，返回 `DEVICE_DIGEST_CONFIG_CHANGED`；
- 不修改现有 K1 schema/helper。

## P0-2：owner claim schema 不完整

`validateOwnerClaimRecord()` 未校验设计必需的 `provider/digestRealm/digestDomain/keyVersion/updatedAt`，也未按状态校验 active/released 字段；同时没有拒绝 `orgId/grantId/serialNumber` 等禁止字段。

### 修复

- 通用必填：provider、digestRealm、digestDomain、keyVersion、ownerOrgId、state、revision、createdAt、updatedAt；
- active：必须有 boundDeviceId、activatedAt、activatedByAuditId；不得有 released 墓碑字段；
- released：不得保留 boundDeviceId；必须有 releasedAt、releasedByAuditId、releaseReason；
- 禁止 `orgId/grantId/serialNumber/MAC/IP/密钥/指纹/住户/人脸` 字段；
- ID 使用现有有界 ID 校验，时间戳使用非负安全整数。

## P0-3：slot schema 仍使用旧 `grantId`

冻结设计要求 active slot 使用 `activeClaimId`（值为当前 grantId），released slot 清除该字段并保留墓碑。当前 helper却无条件要求 `grantId`，会把旧独占模型带入第 2 笔。

### 修复

- 通用字段：orgId/personId/deviceId/cycleId/state/revision/createdAt/updatedAt；
- active：必须有 `activeClaimId`，不得有 releasedAt/releasedByJobId；
- released：不得有 activeClaimId，必须有 releasedAt/releasedByJobId；
- 明确拒绝旧字段 `grantId`；
- H2-b createGrant 仍对任何 released slot 返回 `GRANT_SLOT_CONFLICT`，validator 只负责识别记录结构。

## P1：access device schema 未覆盖冻结记录

当前 helper 未校验 `orgId/createdAt/updatedAt`，也没有校验 ownerOrgId 与 orgId 的本期一致性。

### 修复

- 增加 orgId、createdAt、updatedAt 与有界 ID/安全时间戳校验；
- ownerOrgId 必须等于 orgId；
- status 和 capabilities.face 保持结构校验，face=false 由业务层返回 `INVALID_STATE`；
- 明确 H2-b 不读取或返回 serialNumber。

## P1：一致性 helper 与反例测试不足

- `ownerClaimMatchesDevice` 缺 digestRealm 不一致反例；
- domain helper 没有区分存储损坏与完整配置不匹配；
- 缺 forbidden-field、状态相关字段、时间戳安全整数、空白/超长 ID 反例。
