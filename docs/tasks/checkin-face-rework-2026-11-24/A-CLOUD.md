# A：云端契约、事务与原子建任务

先读 README、COMMON 和固定复审全文。本路实现 R01/R03/R04，为 C 的 R06 提供真实服务端复核；文件归属严格按 COMMON。你是 Harness 实施方，不是最终验收方。

## 必做

1. 修 R01：真实 SDK `cloud://…` fileID 正向贯通，校验可信命名空间、规范对象路径、本人及本申请绑定；裸路径/跨环境/跨用户/跨申请/畸形路径拒绝。不删除归属校验，不把 cloud.downloadFile 能读到文件当作属于本人的证据。服务器配置缺失时失败关闭；新增配置必须有公开的受控管理员配置路径与两端一致校验，不能只在测试中直接填库。
2. 修 R03：消除 txStore 闭包回落外层 DB。配置/名单/房间/租期/申请等权威 gate 与写入、对应 audit 处于实际 SDK 支持的原子边界。明确事务实际支持的点读/写能力及集合查询限制；必要时用可证明的稳定守卫记录，而不是假定 range query 在事务中有效。缺事务能力不能静默放行。
3. 修 R04：任务初建与已有任务分支原子处理，首次 create-only；所有竞争保持 revision 单调，不覆盖 claim/终态，不换 employeeNo。重传 CAS 与审计同样不能破坏状态。
4. 与 C 固定执行前复核协议：下载后，鉴权并重新读取当前权威状态，校验 task/claim/worker/revision、时限和配置/申请/名单/房间/租期/设备绑定。服务端失效、不可用或快照不符时 C 必须零设备执行。复核返回不能只是回显旧 claim；接口白名单、鉴权和错误输出同步更新。

## 必须能证伪的回归

- 同一 SDK 形状 fileID 从 upload 输出传入任务并交 worker；正例不再换成裸路径。
- base DB 与 tx DB 是不同对象；记录权威读取和 audit 的实际上下文，提交失败时业务/audit 全回滚；撤名单/关开关/租期或房间版本变化的交错不继续批准。
- A/B 两创建者读无记录，一方创建后被领取，另一方晚到不能重置；全库快照、revision、claimId、employeeNo、audit、成功 claim 数共同断言。
- 复核时已过期/已撤权/已换房或改租期/错误 worker 或 revision/云不可用等均拒绝；同时保留未过期且快照一致正例。

先报唯一接口清单再让 B/C/D 接入；未确定的 SDK 能力报告精确缺口，不自行引入另一个云平台或绕过认证。完成后只向 lead 交文件清单、原始结果和限制；不 stage/commit/push，不部署、不连接设备。
