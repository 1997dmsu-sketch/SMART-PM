## 阻断项

### P0-1：`access_devices` 未登记 Store

H2 事务必须读取 `access_devices/<deviceId>`，但 `store.mjs` 的白名单、seed 和 LocalStore 旧数据初始化均没有 `access_devices`。CloudStore 的列表读取将失败。

修复：三处登记 `access_devices`，并增加 LocalStore 初始化及 CloudStore 白名单回归测试。

### P0-2：确定性 log ID 存在分段碰撞

当前拼接：

```text
log:{jobId}:{state}:{occurrence}
```

反例已独立复现：

```text
jobId="a:b", state="c"
jobId="a",   state="b:c"
```

两者均生成 `log:a:b:c:1`。

修复：对 jobId/state 分段使用 base64url 或对完整规范输入做固定摘要；增加碰撞反例测试。occurrence 必须为正整数，非法值不得静默回退为 1。

### P0-3：`leasePatch()` 接受损坏状态

已独立复现：

```js
attempts: "0"  // 结果变成字符串 "01"
revision: "1"  // 被静默回退并写成 1
```

这会破坏租约竞争和 revision 条件写。

修复：严格要求：

- owner 为有界非空字符串；
- expiresAt、now 为有限时间戳且 expiresAt > now；
- attempts 为非负整数；
- revision 为正整数；
- 任一非法输入直接 `PARAM_ERROR`，不得默认或转换。

### P1-1：claim/slot helper 对未知状态失败开放

`isReclaimable({state:"corrupt", grantId:"g"}, "g")` 当前返回 true。`releaseClaim()` 也未校验 jobId、时间、当前状态和 revision。

修复：

- 仅 `active` 与 `released` 合法；未知状态失败关闭；
- active 只有当前 owner grant 可视为同一占用；
- released 可重新占用，但新写必须 revision+1；
- release 仅允许从 active 转移；重复 release 应按冻结规则幂等返回或明确冲突；
- jobId、now、revision 严格校验；
- helper 输出不得丢失 owner/device/org 等原记录字段时，调用方必须显式合并并有测试。
