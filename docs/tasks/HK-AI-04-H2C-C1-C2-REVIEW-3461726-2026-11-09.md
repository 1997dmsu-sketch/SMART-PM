## P0：清除 sponsorOccupancyId 可跳过 sponsor 复核

`planEligibilityRefs()` 使用预读的 `expected.occupancy.sponsorOccupancyId` 声明 sponsor ref；`snapshotEligibility()` 却从事务内当前 occupancy 读取 sponsor ID；`validateEligibility()` 没有比较当前与预读的 `sponsorOccupancyId`。

因此，member 在预读后被改成 `sponsorOccupancyId=null` 且 revision 未递增时：

1. 当前 snapshot 的 sponsor 为 null；
2. `if (occupancy.sponsorOccupancyId)` 分支不执行；
3. 其余 primary/slot 合法时可能得到 `eligible=true`。

这违反 Q02 和“关键关系变化失败关闭”。必须：

- 把 `sponsorOccupancyId` 纳入 occupancy 快照严格比较；
- sponsor 始终按预读 ID读取，不按事务内新 ID读取；
- 预读非空 sponsor 被清空、改成其他 ID、目标记录 revision 改变均返回 `REVISION_CONFLICT`；
- 增加三项定向测试并断言只读零变化。

## P0：member/guard 的预读基线不是强制项

`assertGrantRequest()` 没有要求：

- member 必须携带 `expected.primary`；
- 非空 sponsor 必须携带 `expected.sponsor`；
- lifecycle guard 的“存在记录或明确不存在”基线；
- room 与三级 catalog 的完整 ID/revision 基线。

`validateEligibility()` 又只在这些 expected 字段存在时比较 revision。调用方漏传即可关闭部分竞态保护。

修复要求：

1. member 强制 `expected.primary`，其 `_id` 必须等于 `cycle.primaryOccupancyId`，revision 为正安全整数；
2. sponsor ID 非空时强制 `expected.sponsor`，ID 和 revision 均严格匹配；
3. lifecycle guard 使用显式基线：记录对象或明确的 null。预读 null、事务内出现记录也必须触发 retry/conflict；
4. 强制 `expected.person._id=request.personId`、`expected.identityApplication._id=identityApplicationId`、`expected.occupancy.personId=personId`、`expected.cycle._id=request.cycleId`；
5. room/floor/building/community 的 ID、kind、父子关系与正安全整数 revision 在计划阶段完整校验；
6. 对漏字段、错 ID、字符串/负数/超安全整数 revision 补反例。

## P1：C2 未严格验证 hook refs

`withEligibility()` 只检查 `prepared.refs` 是数组，没有检查每项是否为合法 `{collection,id}`。null、空 collection 或空 id 会在 `uniqueRefs()` 中产生 TypeError 或无效事务键，不符合 `ADAPTER_UNAVAILABLE/503` 的受控失败。

要求逐项验证 hook refs；非法元素在开启事务前返回 `ADAPTER_UNAVAILABLE/503`，并补 null、空 collection、空 id 和非对象测试。

## P1：C2 缺少每次 attempt 刷新 refs 与 90/91 合并边界证据

现有一次重试测试两次都返回空 refs，只证明回调执行两次，没有证明第二次事务使用了第二次新计划的 refs。

补测：

1. 第一次返回 `rooms/a` 并触发 retry；第二次返回 `rooms/b`，断言第二次 state 有 b、没有沿用 a；
2. base refs + prepared refs + token refs 去重后恰好 90 条可进入事务；
3. 合计 91 条时事务调用为 0，返回 HTTP 400；
4. prepared refs 与 token/base 重复时只计一次。

同时修正文档注释：`beforeEvaluate` 除 `BLACKLIST_RETRY` 外也会返回正式资格错误；实现当前允许非重试错误透传，注释不得声称“只允许 BLACKLIST_RETRY”。
