## 阻断项

### P0-1：未知 purpose 测试不能证明“读取 body 前拒绝”

测试使用普通 `fetch` 发送完整1MB Buffer，最后只断言返回400。客户端可能已经把全部请求体发送给服务器，因此该断言只能证明“未知 purpose 最终被拒绝”，不能证明服务器在读取大 body 前返回。

修复要求：使用原生 `http.request`/可控流，先发送请求头但不结束或不继续提供 body，并断言服务器在 body 未完成前返回400；同时记录客户端实际发送字节数为0或严格受控。不得仅依赖代码行顺序或完整 Buffer fetch。

### P0-2：并发/队列测试绕过 HTTP，未证明快速503

测试直接导入并调用 `decodeFaceImage()`，只断言第三个 Promise 以“繁忙”消息拒绝。它没有经过 `/api/v2/files`，没有断言 HTTP 503、统一错误信封或上传路由在并发/队列满时的行为，也没有分别证明“并发占满”和“队列占满”两条外部边界。

修复要求：通过 HTTP 并发上传可控的大型合法图片，使用独立测试进程或在应用加载前固定 `FACE_DECODE_CONCURRENCY=1`、`FACE_DECODE_QUEUE=1`；断言：

1. 第一个请求占用解码槽位；
2. 第二个进入有限队列；
3. 第三个快速返回 HTTP 503，错误信封 code 为 `RATE_LIMITED`；
4. 底层任务 settle 后，新的 HTTP 上传恢复成功；
5. 测试结束恢复环境变量，不污染其他用例。

若 Sharp 执行时间难以稳定控制，可为解码调度器增加仅测试可注入的解码函数/闸门；不得在生产路由增加测试后门。
