### 本轮用户最新指令覆盖层（优先于旧流程的当前上线范围）

根 Codex 在本轮转录的用户明确指令为：**“押金，第三方支付入口暂不上线，获取开户码功能取消，微信获取手机号后自动注册。”** 本文据此更新当前范围，不改写已经收口的 v4 原文：

## 2. 角色、流程与编号约定

角色为租客、管理员、材料审核员、财务/收退款责任人，以及业务/法务负责人。角色只是需求职责划分；实际账号、权限矩阵和分权范围须落实，不能因页面存在便认定已有授权。供应商工作线只提供支付/OCR/签署等能力证据，不代替业务裁定。

本期可先规划：微信核验手机号后自动注册/复用用户 → 公开浏览 → 户型 → 房号 → 预约受理。该规划不表示已完成服务器预约集成。

后续完整目标链路：预约受理 → 起租/租期与报价 → 身份证正反面及信息核对/审核 → 留房协议与线上确认 → 全额押金订单 → 渠道支付确认 → 连续72h留房 → 正式入住生成租赁合同＋安全管理责任书 → 线下补签与归档。**押金/支付/付款触发留房本期不开放**，不得把后续目标当作当前可用链路。预约草稿不是受理；材料收件不是审核通过；手机号验证不是材料审核；支付参数不是到账；付款不是线下已签。

`RC-001`–`RC-046` 是本分册稳定编号，后续新增只追加，不重排；旧台账 ID 不被替换。确认状态沿用台账：“已确认 / 已提出待确认 / 建议 / 来源不足 / 暂缓”；统一入口的五类展示中，“来源不足”归入“界面或旧代码线索”，“Kimi 新增建议”单独标识。RC-044—046 均属后者；RC-045／046 的 P1（优先）顺序已确认，业务细则仍待确认。表内最小验收是后续需要证明的结果，**本次均未执行**；新增技术验收只属建议，不构成业务批准。
