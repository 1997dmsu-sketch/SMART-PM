### 1.1 层级硬规则

1. **不得跨层掩盖**：不得用「打开设备写开关」「切 demo」「修改线上数据」「删除集合」「重置标签」掩盖失败。
2. **不得删数据换兼容**：不得删除新集合 / 新字段让旧代码跑起来（沿用 `REL-AI-02` §7.1）。
3. **不得改标签**：回滚以「重新指定版本 / 重新编译冻结提交」实现，不改写、不移动、不删除标签。
4. **不得强推**：回滚不涉及 `push --force`、`reset`、`rebase`、`amend`、`squash`。
5. **数据是最后手段**：只有在确认新写入受影响且备份已验证时才恢复；恢复后必须重新校验组织 / 实名 / 黑名单 / 设备绑定。

## 3. 回滚决策树

```text
发现异常
  │
  ├─ 是否涉及真实设备 / 真实人员 / 真实人脸 / 生产数据？
  │     └─ 是 → 立即停止 + 隔离 + 按事件上报（不先排查）
  │
  ├─ 是否仍在测试窗口、尚未对外？
  │     ├─ 是 → 停止操作 → 记录证据 → 回滚到本窗口起点（R-02 / R-04 / R-06 / R-08）
  │     └─ 否 → 停新增流量 / 写操作 → 评估影响面
  │
  ├─ 影响的是哪一层？
  │     ├─ 平台体验版 → R-01（若无锚点，只能撤回入口 / 重新上传冻结包）
  │     ├─ 代码 / 制品   → R-02
  │     ├─ 云函数       → R-03
  │     ├─ 配置         → R-04
  │     ├─ 数据         → R-05（最后手段）
  │     ├─ 设备         → R-06
  │     ├─ 支付         → R-07
  │     └─ 环境 / 账号  → R-08
  │
  ├─ 回读验证通过？
  │     ├─ 是 → 记录证据 → 由发布指挥决定是否恢复 / 重新进入门禁
  │     └─ 否 → 升级为「无法回滚」→ 隔离 → 停止发布 → 上报
  │
  └─ 是否需要重新审批？
        └─ 是（默认）→ 回到对应 PG 门禁入口
```

### 3.1 回滚执行顺序

1. 停止新增流量 / 写操作（必要时断网、关开关、撤审批）。
2. 保存现场证据（脱敏）。
3. 按层级执行回滚（R-01 → R-08 中受影响的最小集合；不并行）。
4. 回读验证（见 §4）。
5. 记录：时间、层级、锚点、动作、结果、失败项、操作人 / 见证人占位。
6. 由发布指挥决定：恢复测试 / 重新审批 / 终止发布。
7. 未重新审批，不得继续任何写测试或真机用例。

## 4. 回滚验收标准

| 层 | 最小验收 |
|---|---|
| R-01 平台体验版 | 平台显示目标版本；授权测试人员能打开；入口与预期一致 |
| R-02 制品 | 版本号 / 提交 / 大小 / SHA-256 与冻结记录一致；重新编译无错误 |
| R-03 云函数 | 函数列表与快照一致；点名函数存在；无未知函数 |
| R-04 配置 | 启动无配置错误；`allowDeviceOperations=false`；`mode` / 环境与快照一致；不出现「回滚后自动放行」 |
| R-05 数据 | 计数 / ID / revision / 审计与备份清单一致；权限负向用例仍拒绝；无越权扩大 |
| R-06 设备 | 06B RB-08 十项无残留全部通过；设备「隔离封存」；未重新审批不续跑 |
| R-07 支付 | 订单 / 流水 / 退款状态一致；无未决差异；对账完成 |
| R-08 环境 | 网络负责人签字；测试账号禁用；测试机恢复；设备断电挂牌 |

**通用**：任何一层回滚后，若发现「无法证明已恢复」，一律按未回滚处理，设备 / 环境隔离，不进入发布审批。

## 6. 禁止手段（回滚中同样禁止）

| 禁止 | 原因 |
|---|---|
| 打开 `allowDeviceOperations` | 会把测试失败变成真实设备风险 |
| 切换到 demo 模式「先让页面好看」 | 掩盖真实云失败 |
| 修改线上数据 / 手工改订单状态 | 破坏审计与对账 |
| 删除集合 / 删除记录 / 重建集合 | 破坏证据链与权限边界 |
| 改标签、移动标签、删除版本 | 破坏制品锚点 |
| `push --force` / `reset` / `rebase` / `amend` / `squash` | 破坏提交谱系 |
| 关闭 TLS 校验 / 换用其他凭据 | 安全边界 |
| 用旧快照覆盖新审核 / 新证据 | 数据与合规风险 |
| 让未授权人员代登录 / 代操作 | 责任与隐私边界 |
