## 3. P3 的原行为与未来适配要求

原方案把“不支持算法/qop 立即停止”接在原实现描述后，可能被误读为现有保障。本次明确拆开：

1. **原实现事实**：固定 `digest.mjs` 在 qop 包含 auth 时选 auth；否则 `useQop` 为空，生成不含 qop 字段的摘要。对于仅 auth-int 或未知 qop，原编排可能据此发出认证重发，并未实现“此类 qop 必须立即拒绝”。未提供 qop 也走无 qop 分支。这不等于实现 auth-int，也不证明目标接受该摘要。
2. **未来适配要求**：不支持/畸形 qop 应在认证重发前拒绝，不隐式退为无 qop；允许、缺省和算法策略分别显式定义，并按 NT-04 验证。该拒绝逻辑当前未实现、未验证，本次未改 Digest 或网络代码。

六 GET 的方法、路径、查询和顺序、最多十二次传输、G1 身份门禁的待适配状态均未改；没有新增端点、认证回退或执行授权。完整状态继续为 `LIVE_CLI_NOT_INTEGRATED`。
