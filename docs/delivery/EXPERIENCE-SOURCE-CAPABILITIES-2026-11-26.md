## 用户已确认、但本包尚未实现的完整流程

```text
微信手机号注册
    → 服务端确认签约
    → 自动建立本人/合同房屋/对应门禁/租期的远程开门资格
    → 有效租期内直接点击远程开门，无额外申请或二次审批
    → 后续本人上传照片，再开通刷脸通行
```

人脸上传不是远程开门前置，自动开通权限也不是自动发出开门指令。合同失效或不在有效租期内必须拒绝开门；押金及第三方支付不作为基础注册和此流程的前置。

当前缺少下列实现，不能用配置值或测试材料替代：

1. 当前候选没有正式签约确认模块及权威合同记录接线；测试入住的 `auto_approved` 不能冒充签约。
2. `cloudfunctions/unlock/index.js` 只按管理员、`users.houses` 或 public 门禁判断，没有合同/租期授权闭环。不能只写 houses 或打开客户端开关就认定符合新规则。
3. 现有 unlock 路由仅支持 Tuya／TTLock，没有海康云到局域网的受控开门通道。人脸登记 worker 不是远程开门 worker。
4. 最新102云端绑定、唯一性、开关与实际worker入口/配置尚未取得本次白名单实读结果。不得用示例deviceKey、门号或历史指纹填成实际配置。
5. 本次现场两次普通开门仍为 UNKNOWN_NO_RETRY，不能将 HTTP 200 当作门锁释放。协议与现场结果分别保留，不自动重试。
