## P0：slot ID 仍信任事务前 credential.personId

`slotId` 在事务前由 `credential.personId` 生成；事务内 grant 与 slot 数据却使用 `current.personId`。当前只检查 `current.revision === expectedCredentialRevision`，没有确认 `current.personId === credential.personId`。

若损坏记录或并发写在 revision 未正确递增的情况下改变 personId，代码可能写出：

- slot 的 ID 由旧 personId 派生；
- slot/grant 内容记录新 personId。

这会破坏 slot 键与记录内容的一致性。

### 修复

- 事务内在任何写入前比较 `current.personId === credential.personId`；
- 不一致时返回 `REVISION_CONFLICT` 或统一的失败关闭错误，整事务零写入；
- 增加定向测试：预读后把 credential.personId 改为另一值且 revision 保持不变，断言失败、Provider 0、grant/job/slot/log/op key 内容级零变化；
- 正常路径断言 `slotId === grantSlotKey({orgId, personId: slot.personId, deviceId, cycleId})`。
