# B：小程序组件、普通账号反馈与上传衔接

先读 README、COMMON 和固定复审全文。本路负责 R02/R11 及 C2、配合 R01；文件归属按 COMMON。不要编辑云端、worker 或其他路的测试文件。

## 必做

1. 两页改为正确 `checkbox-group bindchange` 结构，处理器与真实数组事件一致；取消勾选恢复禁用，原登录/白名单/用途确认/busy 门禁不放宽。
2. `applyTestCheckin` 仅在 `auto_approved` 且有效非空 applicationId 时展示测试入住受理和人脸入口。`pending_review`/空 ID/畸形返回/未知状态显示既有审核渠道或明确错误，不设为成功，不冒称人工申请已入队。
3. 覆盖页面加载后名单撤销的合法竞态；未通过者零照片上传、零 createFaceTask、零可用人脸入口。
4. 上传仍透传微信 SDK 原始 fileID；服务端对象前缀、房号与租期只取服务端快照。按 A 唯一接口清单适配，不能自己删除协议、改成裸路径或绕过云归属检查。

## 验证

- 静态检查真实 WXML 组件与事件归属，再验证选中/取消及按钮状态；直接调用 handler 的单测不能独自证明组件接线。
- 正常自动通过、pending_review、空/非法 ID、错误/未知结果分别断言 UI 状态、入口和调用计数。
- 上传输出与下一步输入使用同一个 SDK 形状 fileID；接口未定时明确待集成，不把不同 mock 拼成“全链路”。
- 平台实际点击/编译仍待后续体验版步骤；本路不登录、不上传、不部署、不引入 wx 云演示成功 fallback。

完成后交 lead 原始测试/负控、文件和限制，不 stage/commit/push、不自批。
