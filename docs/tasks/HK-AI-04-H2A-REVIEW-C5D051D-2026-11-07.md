# HK-AI-04 H2-a K2 / operation key 复审：`c5d051d`（2026-11-07）

结论：**不通过，方向正确但 K2 域与持久化语义未闭合。H2-b 暂不开始。**

独立验证：集合+服务层 22/22、后台 285/285、根测试 51/51 通过。

## 已通过

- K2 使用独立环境变量和 32 字节严格 Base64；
- idempotency key 限制为 `[A-Za-z0-9._:-]{16,128}`；
- 原始 idempotency key 不再出现在固定 ID；
- org/method/actor 分段使用 base64url，不存在冒号分隔碰撞；
- 固定 ID 携带版本和 HMAC，K1/K2 配置分离；
- 服务层 submit/review/createGrant 已切换到新 key 派生。

## P0-1：K2 配置变化会把旧重放当成新操作

operation key ID 包含 `v{version}`，摘要也包含版本。只要修改 `OPERATION_KEY_VERSION` 或密钥，同一 idempotency key 就生成新 ID，保留期内的旧请求会被重新执行。当前没有 K2 domain guard、旧版本 key ring或受控轮换机制。

按已冻结的“H2-a K2 配置、域、版本”补齐独立 `operation_key_domains`（不得复用 K1 的 `device_digest_domains`）：

- 稳定 head 按 operation realm 定位，不包含版本；
- 保存 `realm/keyVersion/keyFingerprint/revision/createdAt`；
- 首次原子初始化；同 realm 同版本同 fingerprint 继续；
- 版本或 key fingerprint 变化失败关闭，只能走以后单独的受控轮换；
- 不保存 K2 原始密钥。

这样在受控轮换完成前，环境误改不会静默生成第二套 operation keys。

## P0-2：operation key 记录没有保存 K2 版本

submit/review/createGrant 写入 `operation_keys` 时仍只保存 `orgId/digest/result/createdAt`。冻结契约要求记录保存 request digest 与 K2 key version，供重放、审计和轮换判断。

统一记录字段：

- `requestDigest`（替代含义不清的 `digest`，如需兼容须显式迁移）；
- `keyVersion`；
- `operationRealm`；
- `result`、`createdAt`、`orgId`。

重放必须同时验证记录的 realm/version 与当前受控 domain 一致，损坏或缺字段失败关闭。

## P1：HMAC 消息缺少明确用途域

当前消息为 `${version}:${idempotencyKey}`。改为无歧义结构化消息，例如：

```text
JSON.stringify(["KEYED_DIGEST/op", "v1", operationRealm, keyVersion, idempotencyKey])
```

K2 虽已与 K1 使用不同密钥，仍应把用途域和格式版本写入消息，避免以后同一 K2 被其他摘要功能误用。

## P1：错误语义与测试缺口

- 服务层缺失/非法 K2 配置应映射为 `503 NOT_CONFIGURED`，不能作为客户端 `PARAM_ERROR`；
- 补 method、actorType、actorId 隔离测试，当前只直接断言 org 隔离；
- 补同 realm 换版本、同版本换 key、domain 记录不完整/损坏均失败关闭且零业务写入；
- 补 operation key 记录不含原始 idempotency key、保存 realm/version/requestDigest 的断言。

## 实施方案补充裁定

提交前再补齐以下约束：

1. `operation_key_domains` 的 head 与版本历史都必须保存不可逆 `keyFingerprint`。只比较 `keyVersion` 不足以发现“版本不变但密钥被替换”；同 realm 下 version 或 fingerprint 任一变化都必须失败关闭。
2. `keyFingerprint` 只能由 K2 派生，不保存原始密钥；使用固定用途域计算，输出固定长度 hex。不得把 fingerprint 返回客户端或普通 DTO。
3. domain head 固定 ID 不含版本；版本历史 ID 含版本。head/version 任一缺失、kind/realm/version/fingerprint 不一致均 `DOMAIN_INCOMPLETE`；配置与完整记录不一致为 `DOMAIN_MISMATCH`。
4. operation HMAC 消息使用无歧义结构化编码：`JSON.stringify(["KEYED_DIGEST/op", "v1", realm, keyVersion, idempotencyKey])`，不使用自由拼接字符串。
5. domain guard 必须进入所有写 `operation_keys` 的事务：`submit`、`review`、`createGrant`，后续 revoke 同样复用。不能只修 createGrant。
6. 三条路径写入统一记录：`orgId/realm/keyVersion/requestDigest/result/createdAt`；重放读取时严格校验 realm/version/requestDigest，缺字段或损坏失败关闭。
7. 配置缺失、非法 Base64、非法 realm/version、fingerprint/domain 不匹配是服务端配置错误，统一 `503 NOT_CONFIGURED` 或约定的 domain 错误；客户端 idempotency key 格式错误仍为 `400 PARAM_ERROR`，两类错误不得混淆。

测试除原清单外，必须覆盖“同版本换密钥”被 guard 阻止，以及 submit/review/createGrant 三条路径首次初始化/复用同一 domain、记录字段一致且不包含原始幂等键。

### Fingerprint 与错误分类最终约定

- 不使用自由字符串拼接再 `sha256(realm + version + key)`；改用 K2 作为 HMAC 密钥，对结构化用途域计算：`HMAC-SHA256(K2, JSON.stringify(["KEYED_DIGEST/op-key-fingerprint", "v1", realm, keyVersion]))`。
- fingerprint 只用于受限 domain 记录比较，不进入普通响应、日志或客户端 DTO。
- 已存 head/version 两条记录完整且彼此一致，但与当前配置的 version/fingerprint 不同：`DOMAIN_MISMATCH`。
- head/version 缺一、kind/realm/version/fingerprint 彼此矛盾、字段缺失或格式损坏：`DOMAIN_INCOMPLETE`。
- 两类错误都必须在业务写入前失败关闭，但不得合并为同一原因；测试分别覆盖。
