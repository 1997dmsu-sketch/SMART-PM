## P0-1：owner claim 状态字段仍不符合冻结设计

当前 validator 缺少通用字段 `digestDomain`；active 记录缺少 `activatedAt/activatedByAuditId`；released 记录仍要求保留 `boundDeviceId`，并使用 slot 的 `releasedByJobId`，而冻结设计要求清除设备绑定并记录 `releasedByAuditId/releaseReason`。

### 修复

- 通用必填：`provider/digestRealm/digestDomain/keyVersion/ownerOrgId/state/revision/createdAt/updatedAt`；
- active：必须有 `boundDeviceId/activatedAt/activatedByAuditId`，不得含 released 墓碑字段；
- released：不得含 `boundDeviceId/activatedAt/activatedByAuditId`，必须有 `releasedAt/releasedByAuditId/releaseReason`；
- 继续拒绝 `orgId/grantId/serialNumber`，并补齐冻结设计列出的敏感字段黑名单。

## P0-2：domain helper 未复用正式记录 validator

`digestDomainMatchesDevice()` 只手工检查 kind/provider/realm/version，没有调用 `validateDigestDomainRecord()`。因此缺少 head `revision/createdAt` 或 version `enabledAt` 的记录仍可能被当成完整记录。

### 修复

- 对 head/version 分别调用 `validateDigestDomainRecord()`；validator 抛错统一映射为 `DOMAIN_INCOMPLETE`；
- 两条记录各自有效但彼此矛盾，仍为 `DOMAIN_INCOMPLETE`；
- 两条记录完整一致但与 device 配置不同，才返回 `DEVICE_DIGEST_CONFIG_CHANGED`；
- 保持不新增、不要求 K1 fingerprint。

## P0-3：slot 缺少生命周期时间字段

当前 slot validator 已正确改用 `activeClaimId`，但没有校验通用 `createdAt/updatedAt`，active 也没有要求 `activatedAt`。这会允许不完整记录进入第 2 笔事务判断。

### 修复

- 通用必填增加 `createdAt/updatedAt`；
- active 必须有 `activatedAt`，不得有 released 墓碑字段；
- released 不得有 `activeClaimId/activatedAt`，必须有 `releasedAt/releasedByJobId`；
- H2-b 仍禁止复用任何 released slot。

## P1：有界字段与反例覆盖不足

- ID 目前只检查非空字符串，未复用现有有界 ID 规则；
- `ownerClaimMatchesDevice` 的测试名声称覆盖 realm，但没有 `digestRealm` 不一致反例；
- 缺 owner claim 状态互斥、domain 时间字段缺失、slot 时间字段及控制字符/超长 ID 反例。
