# 预约看房与押金预签约

日期：2026-11-16。代码基于 main `282a20f`，在独立分支 `feat/rental-reservations-presigning` 实现。本功能不依赖未合并的 07B/07D/H4-c 分支，不接门禁、不自动创建入住授权。

## 已实现的流程

小程序“房源详情 → 预约”或“我的 → 预约看房与预签约”：

1. 授权手机号登录；按实际物业目录选择户型，再选择房号，只展示已上架、非公共用房且正确关联 rooms/layout 的房源。同一楼栋详情进入时仅选该楼栋；从“我的”进入可选择全部已上架户型。
2. 填写联系人、看房日期与时间，真正提交云端预约，在“我的看房预约”查看状态。手机号取登录结果，不采信客户端传入的用户身份。
3. 管理后台新增“预约与预签约”，仅 admin 可访问；确认看房、审核身份证正反面。普通运营和只读账号均不可查阅证件。
4. 用户阅读实际证件收集说明并同意后上传本人身份证正反面；加密保存，后台逐份查看并审计。无 OCR、公安核验或人脸识别，审核由物业负责核对。
5. 预约确认且材料审核通过后，按已启用的自有模板生成合同；用户查看具体金额、留房时长和到期规则并主动勾选同意，保存合同版本与确认快照，创建押金订单。
6. 接入微信支付 JSAPI 后，用户付款。服务端验签主动查询或验签/解密支付回调，核对 appid、mchid、商户订单号、付款人、金额、币种、流水和时间；客户端支付成功提示不会直接留房。
7. 核验到账后留房 72 小时（默认）。后台确认已完成正式合同签署后，将订单记为已签约、房源标记为已租。本功能记录预签约确认，未提供 CA 电子签章或声称完成具备第三方存证的正式电子合同签署。

## 押金模板和留房规则

后台“押金规则与自有合同模板”配置：

- 押金 = 月租 × 押金月数 + 固定附加金额，默认 2 个月 + 0 元；金额以整数分计算，月数允许 0–12、最多一位小数。价格一律取服务端当前房源，不采信前端金额。
- 默认留房 72 小时，从微信支付成功时间开始；确认合同后预留 15 分钟付款窗口。未付款占位到期可重新预约/下单。
- 用户指定的暂定规则为“留房期限届满未完成正式签约，押金不退”，后台也可切换为“物业审核处理”。模板启用前，物业须将实际生效条款写入自有模板与用户页面确认文本；本代码不代替你们确定最终合同条款。
- 规则修改只影响新确认的订单；已确认的合同文本、金额、规则、模板版本保留快照。任何变化都会使旧报价失效，用户须重新查看后确认。
- 重复提交使用稳定提交编号；同一房号由数据库事务中的单一 hold 记录保护。两人并发只能一个订单占房；付款回调重放不能延长留房。
- 超时付款、原占位已被替换，或客户端已缓存旧支付参数但材料随后变更的到账标记为 `refund_required`，不夺取新订单房号。此类款项不按“不退”规则处理，须在微信商户平台核对并退款；本版没有自动退款 API，也没有手工“改成已支付/已退款”的入口。
- 已付款且仍有效留房或已正式签约时，用户不能直接重传材料，须联系物业处理；不会自动改写已付款合同。
- 付费留房到期的展示状态由服务端时间计算；hold 截止时间到期即不再阻挡新订单。到期不会触发设备权限变更、补扣款或自动正式签约。

## 导入自有合同模板

现阶段未收到你们的实际模板，产品没有放入虚构的示例合同，默认不启用预签约及证件收集。后台支持粘贴纯文本或导入 UTF-8 `.txt`；Word/PDF 先转换文本并逐条校对。保留条款内容，变量使用：

| 变量 | 内容 |
|---|---|
| `{{tenantName}}` | 预约联系人姓名，须经材料审核核对 |
| `{{roomLabel}}` | 小区、楼栋、房号 |
| `{{monthlyRent}}` | 当前月租（元，2 位小数） |
| `{{deposit}}` | 押金总额（元，2 位小数） |
| `{{holdHours}}` | 付款后的留房小时数 |
| `{{expiryPolicy}}` | 生效的到期处理规则 |
| `{{appointmentId}}` | 预约编号 |

必需变量：tenantName、roomLabel、deposit、holdHours、expiryPolicy。未知变量会阻止启用。模板每次保存增加版本；不能在已确认订单中替换合同正文。未配置模板可预约看房；没有商户时可查看合同，但不能创建可付款订单或谎报留房成功。

## 身份证材料

- 服务端读取 `RENTAL_IDENTITY_KEY_B64`：独立 32 字节密钥的规范 Base64。只放云函数和后台受控环境变量，禁止放 Git、小程序包、日志或聊天；部署平台也不要开启证件上传参数或请求体日志。密钥托管与数据备份分开；未提供密钥会阻止上传及查阅。
- 图片接受 JPG/PNG，单份上限约 500KB；小程序压缩上传，经服务端类型/长度检查，以独立随机 IV 的 AES-256-GCM 加密，AAD 绑定材料 ID、用户、预约和正反面。数据库不保存明文照片，不生成公开云存储地址；列表不返回密文或图片内容。
- 小程序不将图片放入 storage 或 Page.data；上传完成/失败后清除选择与压缩产生的临时文件。不删除用户相册原件。
- 上传必须绑定当前证件收集说明/模板版本；说明变化须刷新并重新同意。更换材料会重置审核状态，不能沿用旧审核直接付款。材料重传与当前待支付订单失效、释放其付款占位在同一事务完成；旧单即使材料重新审核通过也不能恢复支付，必须重新确认合同并创建新单。生成支付参数前、返回参数前和处理到账时都复核订单绑定的正反面材料、有效期及当前审核状态。
- 默认材料 30 天后不可查阅，按服务端时间判断。`rental-retention` 每日凌晨 3 点的云触发器清空到期密文/IV/tag，并保留最小清理审计；后台也有“清理到期证件”。部署时必须核验触发器真实来源及运行成功，不能仅依据配置文件宣称已删除。
- 初始证件收集说明为空：物业须填写实际收集主体、用途、查阅人员、30 天保存期及联系/删除渠道，再启用。隐私保护指引需在微信公众平台登记选择相册/拍照、身份证信息用途；小程序已启用隐私检查并调用隐私授权接口。
- 不支持在尚有材料时直接换加密密钥；须先制定恢复/轮换方案。密钥不可恢复时不会输出错误解密内容。

## 微信支付接入与难度

无需先接聚合支付第三方；已有微信小程序可走微信支付直连 JSAPI。主要外部工作是商户开户、AppID 绑定、支付权限、回调 HTTPS 地址、密钥托管与真实商户联调。当前无商户，因此默认 `paymentReady=false`；不会生成模拟可付款凭据。

云函数和后台支付状态检查所需变量（值全部来自受控平台，不放文档）：

| 变量 | 作用 |
|---|---|
| `WX_PAY_APPID` | 实际小程序 AppID，与商户绑定 |
| `WX_PAY_MCHID` | 微信支付直连商户号 |
| `WX_PAY_SERIAL` | 商户 API 证书序列号 |
| `WX_PAY_PRIVATE_KEY` | 商户 RSA 私钥 PEM |
| `WX_PAY_PLATFORM_SERIAL` | 微信支付平台证书序列号或平台公钥 ID |
| `WX_PAY_PLATFORM_PUBLIC_KEY` | 对应平台验签公钥 PEM |
| `WX_PAY_API_V3_KEY` | 32 字节 APIv3 密钥，用于通知解密 |
| `WX_PAY_NOTIFY_URL` | 已开通的云函数 HTTP POST 访问地址，必须 HTTPS |

代码使用固定域名 `api.mch.weixin.qq.com` 的 v3 JSAPI 接口，RSA 签名请求，校验平台响应签名、序列号及 5 分钟时间窗口，回调验签并 AES-GCM 解密。必须校准服务器时间，部署平台证书/公钥更新流程；签名/证书不匹配时失败关闭。没有自动平台证书拉取轮换，本版由运维更新受控配置。

开通云函数 HTTP 访问时配置 POST 支付回调；HTTP 调用只接受可验签的微信支付通知，不根据 URL、客户端用户信息或 Type 字段放行。失败返回 500 供微信重试；重复成功通知为幂等。正常客户端 action 无 applyPayment 或 admin 权限入口。禁止在网络不可用时用“前端支付成功”或人工标记代替服务端核验。

真实支付上线前必须演练：小额支付到账、取消支付、网络超时后查询、重复通知、金额不符拒绝、超时到账需退款、不重复扣费、留房到期、商户退款对账。尚未开户前这些不能标记为通过。自动退款、正式电子签章、OCR/实名核验与高容量索引分页为后续扩展。
