## 2. E1：限定目标、GET 白名单、连通与能力验证（仅未来授权执行）

### 2.1 目的与“成功”的定义

E1 只回答三个问题：

1. 在**单一已批准目标**上，HTTPS + Digest 能否完成一次受控的只读握手；
2. 6 个白名单 GET 各自返回什么状态、型号/固件/能力节点是什么；
3. 哪些能力节点**明确存在**、哪些**明确不存在**、哪些**读不到**。

**E1 成功不等于设备支持人脸业务**。E1 完成只表示“只读证据采集完成”；是否支持上传/删除仍须由 E2 的能力先证与 E2 实测决定。

### 2.2 目标限定

| 约束 | 要求 |
|---|---|
| 目标数量 | 单台设备、单主机、单端口；不得并行第二台或第二端口 |
| 目标标识 | 只用内部 `deviceRef`；不得把序列号/MAC 当引用 |
| 地址 | 由网络负责人在**仓库外**分配并写入密封附件；卡内只出现 `<DEVICE-IP>`、`<DEVICE-REF>` |
| 主机白名单 | `HIKVISION_PROBE_ALLOWED_HOSTS` 为逗号分隔列表（工具接受多主机，不自动强制单主机）；须按 §2.5.1 独立无网络配置核对，解析后恰好一项且与唯一批准目标相同；不允许 CIDR、通配；**dry-run 不核验主机/端口或白名单** |
| 端口 | 必须显式、非空、纯数字；不得依赖默认 `443/8443` 回退 |
| 型号前置 | `HIKVISION_PROBE_EXPECTED_MODEL` 必填且与批准型号逐字一致；`deviceInfo` 型号为空/不一致即中止 |
| 网络 | 隔离 VLAN/交换机，无生产上联、无默认路由、无生产 DHCP/DNS；**禁止 ping 扫描、端口扫描、网段探测、ARP 扫描、发现类工具** |
| 重定向 | 任何 3xx 直接失败；不得跟随到其他主机 |
| 降级 | 不得从 HTTPS 降级到 HTTP；不得关闭证书校验；不得从指纹模式回退到系统信任链或 CA |

| ID | 方法 | 路径 | 目的 | 备注 |
|---|---|---|---|---|

1. 路径与查询串**逐字匹配**；额外参数、尾随斜杠、大小写变体、`..` 一律拒绝。

3. 白名单外端点没有代码路径可达；任何“顺手试一下”的端点都不属于 E1。
4. 端点返回 404/403 只记录该端点结果，不据此推断设备不支持；只有设备明确返回“不支持”才可写 `unsupported`。

| 禁网检查窗口与配置绑定 | 核对和 dry-run 期间不设置 `HIKVISION_PROBE_ALLOW_READ=true`；随后单次执行使用同一份受控主机/端口/白名单/型号配置，不能在核对后替换 | `allowReadDisabled=true`、`sameConfigBound=true` |

**未满足即停止**：当前尚无本卡定义的可执行核对器与复审证据。未来须另案取得固定版本、可复核的无网络核对能力及该次结果，且 §2.5 全部准入条件和 E1 单独授权齐备，才可执行 E1。缺核对器、缺证据、任一结果非预期、配置改变或匹配未知，均不得设置 `HIKVISION_PROBE_ALLOW_READ=true`。本段不授权实现核对器或连接设备。

### 2.5.2 E1 准入与采集项分开

- **E1 前置**：§2.5 的审批、唯一目标/显式配置、最小权限账号引用、线下证书指纹核验、隔离网络、工具版本、POSIX 权限、时间窗、人员和停止条件必须全部满足；缺一即不执行。
- **E1 采集**：目标实际返回的固件/硬件版本、认证挑战、能力节点和计数属于 E1 要采集的证据，不要求事先全部已知；采集失败按 §2.7/§2.8 记录 `unknown` 或中止，不能推断支持或不支持。
- **E2 前置**：另行授权、§3.1 能力先证、字段/图片约束、写前不存在基线和清理对象绑定均须满足；所需能力/字段/查询或删除语义为 `unknown`/`unsupported` 时不申请、不执行相应写测试。E1 获准或采集完成不传递 E2 授权。

### 2.6 执行顺序（未来，仅在批准后）

1. `set +o history`；用无回显输入注入主机、端口、账号、密码、指纹、期望型号；不把值写入命令行、脚本、日志。
2. 保持 `HIKVISION_PROBE_ALLOW_READ` 未启用，先用另案已复审的配置核对器按 §2.5.1 独立无网络核对，确认唯一主机/端口/型号与批准单匹配；仅回填布尔/计数，不输出实值。缺核对器或证据即停止。
3. 对同一份受控配置执行 dry-run，仅核对 6 个 GET 的方法、路径与顺序；复核配置核对结果、§2.5 准入条件及授权均有效后，输入一次性确认串。dry-run 不证明主机/端口合法；配置任一变化即使先前核对失效，须重新核对并复核授权范围。
4. 设置 `HIKVISION_PROBE_ALLOW_READ=true`，**只执行一次**。
5. 执行结束立即 `unset` 全部注入变量；保留 `checks`、`aborted`、`report.json`。
6. 在 1 小时内完成证据回填；删除原始响应与临时目录；复核工作区无变更。

**禁止：** 重跑、放宽超时、关闭校验、改走 CA、补发请求、并行多会话。

### 3.4 写前不存在基线、写入确认与设备侧查询

1. **写前查询**：在 E2 独立批准的只读查询范围内，按本次拟用 `employeeNo`/人员编号及已确认的关联人脸记录查询方式，确认人员与关联对象均不存在；留存查询条件（脱敏）、明确的不存在结果、采集时间、设备/固件引用及人脸库计数基线。编号已存在、关联对象已存在、查询权限/语义不足、结果不完整或 `unknown` → **不创建、不覆盖、不上传、不删除，停止并隔离待复核**。前缀、计数差值或“测试编号”命名均不能替代存在性确认。
2. **本次对象绑定**：将 `approvalId`、设备引用、写前不存在证据引用、精确人员编号/关联库引用、照片哈希与本次单次请求绑定。设备返回标识若与此绑定不一致，停止；不得认领同前缀的既有对象。
3. 仅在写前基线与其余准入均满足时只提交**一次**；记录请求摘要（字段名 + 合成值类别，不写真实 PII）、响应状态、错误码、时间。
4. `ResponseStatus`/HTTP 200 只记为“已受理”，不得写“已生效”。
5. 必须做设备侧查询：按该精确人员编号查询人员与关联人脸记录，并与绑定对象逐项核对；记录写入前后 `Count` 差值。计数变化不能单独证明对象归属。
6. 查询不到但响应成功、写结果未知或归属无法确认 → `unknown`，停止后续业务步骤并隔离设备；仅在原 E2 审批允许的核查/清理范围内按已确认语义核查，不盲删、不补发创建。
7. 查询到且能证明为本次创建对象 → 留存脱敏标识、查询时间、查询条件及绑定证据，方可进入 §3.5 的对应清理；仍不得写“业务可用”。

### 3.5 删除与清理

| 步骤 | 要求 |
|---|---|
| 删除对象 | 只删除 §3.4 写前确认不存在、且能以本次请求/设备返回或核查结果证明为本次创建的精确人员及关联人脸对象；核对设备/库/对象标识与绑定证据，不按 `E2SYN...` 前缀批量匹配；不得删除既有或归属未知对象/其他库 |

| 完成判定 | 有异步进度（如 `DeleteProcess`）时轮询到 `success` 或明确终态；超时即停止 |
| 清零验证 | 人员查询返回 0、人脸库计数回到写入前基线；记录前后计数 |
| 失败处理 | 清理失败/无法证明清零/无法证明对象由本次创建 → **设备隔离**，不得归还/上线；不得盲删或反复重试；写结果未知不等于获准删除预先存在对象 |
| 重试 | 任何重试都需要新的审批单与新的时间窗 |
| 证据 | 写前不存在结果及计数基线、本次请求/对象绑定、删除请求/响应摘要、进度、前后查询、计数、操作人/见证人 |
