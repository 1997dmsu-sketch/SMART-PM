入住＋人脸登记测试配置

仅本地管理后台可配置；所有写操作留审计。本页不展示、不接收任何设备密码、证书或私钥。

默认关闭：测试自动通过开关缺省为关闭；关闭后新申请立即不再自动通过。
不填租期不自动通过：租期起止必须由负责人手动填写；未填、取消或过期时页面显示「待配置」，不会回退长期或自动取今天。
秘密边界：设备地址、账号、密码、公开证书路径、私钥与 pin 只存在于本地受控 worker 的 Git 忽略文件中，不在本页、云端、小程序或日志出现。
建议配置顺序：填申请版本号 → 设 worker token → 设可信云存储命名空间 → 绑定 102 → 手填租期 → 设测试账号 → 开派发开关 → 最后开自动通过开关。自动通过开关有前置校验：版本号、worker token、可信云存储命名空间、102 绑定与有效租期缺一不可，否则拒绝开启且不写库；派发开关与它是两个独立开关，只控制 worker 是否领取任务。

测试自动通过开关

申请版本号（服务端判据）

负责人上线时填写，必须与小程序提交的 applicationVersion 完全一致；留空时申请必然失败。这是申请版本匹配字段，不是自动通过开关，也不是派发开关。

可信云存储命名空间（fileID 契约）

服务端只接受命名空间与此处完全一致的真实 cloud://… fileID。填写真实环境 wx.cloud.uploadFile 返回 fileID 中 cloud:// 与第一个 / 之间的整段（以现场联调实际返回为准，例如 prod-env-id.7465-prod-env-id-1300000000）。未配置时上传建任务失败关闭，自动通过开关也无法开启。

派发开关（worker 领取任务）

默认关闭。仅开启后本地 worker 才会通过 claimTask 领取排队任务；关闭时排队任务不被派发，也不会自动重试。此开关与上面的「测试自动通过开关」相互独立，开的时机也不同：先让自动通过链路可用，需要设备下发时再开派发。

worker token（本地随机凭据）

这是负责人本地签发的随机凭据，供 worker 主动领取/上报任务使用，不是设备密码。服务端只保存 SHA-256，页面只显示「已设置/未设置」，明文提交后立即从输入框清除，不回显、不缓存、不写日志。禁止贴聊天、提交 Git 或打进发布包；轮换时直接重新设置即可。

102 唯一房间绑定

展示房号固定为 102；需唯一绑定稳定 ID 与测试门号。绝不从多条同号房中默认取第一项。

指纹须由负责人实际核验设备全天计划（周计划/假日/时段/次数）后填写，属设备可信材料；未填或不一致时上报不会进入「设备查询已确认」，这是预期的失败关闭行为。

测试租期（负责人手填）

起止日期由负责人手动填写，按 Asia/Shanghai 保存为起始日 00:00:00 至结束日 23:59:59 的固定有效期，租期内每天 24 小时。不提供「一年 / 长期 / 自动今天」选项；未填或取消不会自动通过。

测试账号名单（openid）

一行一个 openid，只有名单内账号才可能自动通过；名单之外保持原审核流程。openid 由负责人在本机登记，不贴聊天、不写小程序。
