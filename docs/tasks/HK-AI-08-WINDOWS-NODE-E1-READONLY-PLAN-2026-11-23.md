## 2. 已有能力与仍缺的接入点

1. 原 `fs-safe.mjs` 在 Windows 下仅做 Node `chmod`，跳过 POSIX mode 断言，不检查 DACL、所有者、继承或重解析点。原 `mkdir` 可递归使用既有目录，`writeFile` 可覆盖既有文件；这些行为不能独立证明 Windows 证据保护或本次对象归属。
2. 既有 Windows ACL 工具只证明其本次新合成对象，不能自动替代真实 Node 写入前后、原始响应和报告写入路径的检查。本轮局部核验的结论不得超出实际覆盖的 `fs-safe` 函数与合成对象。
3. 原 CLI 使用 `process.env` 构建配置，`runProbe` 完成后再次读取输出目录变量；配置未深冻结，允许端口与若干参数有默认回退。不能由“离线 checker 先 PASS、稍后启动原 CLI”推出同份配置绑定。
4. 原 `runProbe` 对 G1 非 200 仅记 `HTTP_STATUS`，该错误不在致命错误集合，仍可能进入 G2。只有 G1 返回 200 后型号空/不符才明确中止。未来桥必须补足 G1 任意非 200、不可解析、型号未知/不匹配均阻断 G2 的门禁；本轮没有实现或实测该改动。
5. 原 HTTP 实现具有 socket inactivity timeout 和响应字节上限，但没有可见的绝对总 deadline；持续缓慢到达的数据可能不触发 inactivity timeout。未来桥须证明真正总时限，不能把原参数名或注释当完成证据。
6. 原输出报告包含实际端口、主机摘要及任意设备错误文本，CLI 还打印输出路径；不能将原报告或 stdout 整体当作可提交的脱敏证据。固定默认盐生成的主机摘要不是安全的公开配置绑定证据。

## 4. TOCTOU 四层处置与残余风险

| 层 | 未来必需处置 | 不能声称已解决的部分 |
|---|---|---|
| 配置层 | 一次读取、规范化私有副本、同源冻结投影/执行视图绑定、逐级冻结、禁止重读 env/outDir/CA、固定代码版本 | 同一字符串路径或同一个随机引用不能证明同份配置；当前完整桥未实现 |
| 文件层 | 网络前创建新的本地固定 NTFS 随机保护根；所有者和精确两 ACE/DACL/继承验证；只认领本次新对象；写入/关闭/必要操作前后复查路径、对象身份和 ACL | `realpath`、路径逐级检查、Node stat 或相同路径不原子固定对象；不能假设 Windows 的 `O_NOFOLLOW` 或 chmod 提供 POSIX 等价保护 |
| 网络层 | 唯一目标与 TLS pin 固定；不跟重定向/响应 URL；若批准 DNS，必须在执行时解析并绑定实际 peer，重新解析或 peer 改变即阻断 | 离线 checker 不解析 DNS，不证明路由或对端；已审原传输未提供完整 DNS/peer 绑定证据 |

输出根必须在网络开始前确认可用，不能像原 CLI 在完成请求后才首次确定输出目录。未来写入需明确 CreateNew/独占句柄、不可覆盖和文件身份核验；原 `writeFile` 的默认覆盖语义不是该保证。仅允许工具自身清理本次已知文件及空目录，未知子项、ACL/身份变化或清理失败立即停止，保留引用交复核；不得递归删除、放宽 ACL 或改用旧目录。

文件身份应使用已验证可靠的 Windows 句柄/卷和文件 ID 等机制；若平台不能提供可靠绑定，必须如实阻断，不能用路径相同代替。所有路径/ACL 检查仍不能原子消除拥有相同用户权限的恶意并发、祖先替换、内存修改或管理员攻击。本方案不承诺 Windows/POSIX 全场景等价，不以阶段性复查冒充无 TOCTOU 风险。

建议未来受控配置优先使用有权方确认的 literal IP，减少 DNS 重绑定面；这是目标定位建议，不是恢复隔离网络要求。若选择域名，须另补 DNS 解析结果、连接 peer 与 TLS 身份的绑定实现及证据；不得把格式合法的 DNS 名当作已经绑定真实设备。

## 7. TLS、超时及响应处理边界

原工具存在系统信任链模式与 pin-only 模式；既定 E1 采用线下核验的叶证书 SHA-256 固定模式，最多两枚以支持受控轮换，不回退到 CA/系统链或关闭 pin。

必须准确继承 pin-only 的已审语义：原实现临时关闭系统信任链及主机名校验，用叶证书原始字节 SHA-256 常量时间比较；没有证书或不匹配即拒绝。该模式不验证主机名或有效期，证书过期仅告警；不得宣称同时完成标准链、hostname、有效期和 pin 校验，也不得将 `rejectUnauthorized=false` 脱离 pin-before-send 门禁单独使用。

原代码创建请求后立即 `request.end()`，再在 socket `secureConnect` 事件检查 pin。**“任意 HTTP 字节（含 Authorization）发送前已验证叶 pin”仍须适配实现及独立时序证据，当前未证明。** 不以源码注释代替该证据；错误 pin/无证书必须证明服务端收到 HTTP 字节数为 0。不能在已经发送认证头后仅销毁 socket 来宣称满足该条件。

原默认 inactivity timeout 为 10000ms、原始响应上限 262144 字节，只作为原代码基线，不作为真实设备参数默认回退。未来批准配置须显式固定正数/上界，新增真正绝对 deadline（每传输及整个会话），持续分块输入也不能延长。对声明或实际字节超限、总时限、TLS/网络/响应流错误立即中止，不自动调大阈值、重试会话或改协议。解析需要边界和错误状态，不执行 XML 外部实体、响应 URL、脚本、模板或设备提供的后续动作。
