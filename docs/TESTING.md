# v0.1.0-beta.1 测试交付说明

交付类型：**原生微信小程序交互测试版**。源码 Git 标签为 `v0.1.0-beta.1`。
本包可交给测试人员导入；尚未获得微信编译/真机/业务验收通过结论。

## 获取与启动（无需生产账号数据）

1. 下载 GitHub 标签 `v0.1.0-beta.1` 的源码 ZIP，或本次生成的 `SMART-PM-v0.1.0-beta.1.zip`。
2. 解压本次交付包，进入 `SMART-PM/`，在微信开发者工具导入该目录，选择小程序项目。
   GitHub 自动源码包的外层目录名不同，选择其中有 `project.config.json` 的目录即可。
3. 确认代码目录为 `miniprogram/`，基础库设置为 `3.16.3`，使用稳定版微信开发者工具。
4. 默认 `touristappid` + `demo` 模式；前端无 npm 依赖，不需要构建 npm 或部署后端即可测试演示交互。
   若工具不接受游客模式，填写有权限的测试 AppID，但保持 `config/runtime.js` 的 demo 配置。
5. 编译进入首页，从底部5个入口测试。我的页底部应显示 `v0.1.0-beta.1 · 交互测试版`。
6. 云函数依赖只在进行后端开发时安装，不应将 `node_modules/` 打入小程序包。

当前机器没有微信开发者工具，以上导入流程仍需测试人员执行验证。
如需手机扫码的微信“体验版”，还需有效 AppID、开发者工具登录与该应用的上传权限；
源码ZIP/Git标签并不等同于已上传微信平台或已生成体验二维码。

## 默认配置与数据

- mode = demo，cloudEnv 为空，allowDeviceOperations = false。
- 页面显示设计演示标识，不会发送云函数请求或操作真实门锁。
- 收藏、内容关注、房源备注和预约草稿仅保存在当前模拟器/设备，不同步物业。
- 不在测试数据中填写真实姓名或手机号；预约校验可用合成测试数据。
- 重新测试可通过开发者工具“清缓存 → 全部清除”，再重新编译；这会删除本机测试草稿。

## 自动检查

```bash
npm test
npm run check
# 安装后端依赖后可执行：
node scripts/verify-import.mjs
```

自动测试使用模拟的微信API，验证数据映射、错误处理、演示隔离和关键页面行为；
静态检查验证路由/事件绑定/模板结构/图片引用/主包大小/版本一致性。
它们不能替代微信编译、截图对比、真实手机号、支付、蓝牙和云端权限验证。

交付ZIP在打包时会从 Git 提交导出，并在独立临时目录重新执行前端测试及静态检查；
结果写入旁置 `test-report.txt`。`release-manifest.json` 记录完整提交号、包大小和SHA-256。
