| 生物识别告知同意、代提交和未成年人规则不完整 | 合规与用户争议 | HK-P0-03/HK-P1-02 |
| 保存期限和删除策略未配置 | 人脸资料超期保存 | HK-P0-03 |
| 审核理由、撤销理由和审计导出缺失 | 无法追责和复核 | HK-P1-01 |
| 运维人员权限过大 | 可越权查看原图或操作设备 | HK-P0-03/HK-P1-01 |
| 没有现场备用通行方案 | 设备故障影响住户进入 | HK-P1-03 |
| 没有住户说明和客服流程 | 状态失败时投诉量增加 | HK-P1-02/HK-P1-03 |

## 5. 并行开发安排

在不违反前置门禁的情况下，最快并行方式：

```text
轨道 A：HK-P0-01 厂商资料与路线 ───────→ HK-P0-05 真实 Provider ─→ HK-P0-07 联调
轨道 B：HK-P0-02 DB 集成 ─→ HK-P0-03 私密文件 ─┐
                         └→ HK-P0-04 服务/Mock ─┼→ M1
                         └→ HK-P0-04A 隔离云探针 ┤
轨道 C：API 契约冻结后 ─→ HK-P1-01 后台 ───────┘
                         └→ HK-P1-02 小程序（灰度后第二批）
轨道 D：路线冻结后 ─────→ HK-P0-06 网络通道 ───→ HK-P0-07 联调
联调通过：HK-P1-03 单小区灰度 ─→ M3
```

关键路径是 `P0-01 → P0-05/P0-06 → P0-07`；厂商资料没有到位时，即使软件模拟流程完成，也不能宣称真实海康人脸门禁可用。

## 6. 每个 AI 的提交要求

认领时回复：

```text
认领任务：HK-...
工作分支：feat/...
基准提交：...
本轮交付：...
本轮不做：...
外部依赖：...
预计完成：...
```

完成时必须提供：

1. 分支、完整 commit 和 PR。
2. 修改文件及共享文件单独提交说明。
3. 已执行测试、未执行测试及原因。
4. Mock/隔离测试/生产证据范围。
5. 新增权限、密钥要求、数据集合和迁移/回滚方法。
6. 测试人脸、设备权限和文件的清理证明。
7. 未关闭阻碍，不得用“基本完成”代替。

## 7. 上线阻断条件

出现任一项时不得开启真实设备：

- 目标型号和固件接口仍靠猜测。
- 没有隔离测试设备新增与删除闭环。
- Mock 结果可能进入真实授权状态。
- 人脸文件可被公开访问或无审计读取。
- 无有效入住、实名或组织校验仍能创建授权。
- 发送后超时会自动重复新增/删除。
- 退租后业务授权未立即失效。
- 撤权失败没有告警和持续重试。
- 厂商密钥、人脸 Base64、永久 URL 或完整个人信息进入日志/仓库。
- 测试完成后无法证明设备和平台无测试人脸残留。
- 没有设备级灰度白名单和紧急停用方案。
