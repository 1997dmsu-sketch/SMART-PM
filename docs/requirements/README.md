# SMART-PM 需求统一入口

更新基线：2026-11-20；本索引位于独立文档分支 `docs/requirements-register`，不代表已合并或发布。

本目录是项目需求状态的统一入口。先看[需求台账](REQUIREMENTS-REGISTER.md)了解全部已知功能线索及各自状态，再看[待决与阻断](OPEN-DECISIONS.md)了解尚需裁定或外部材料的事项。台账引用工作线原文，不替代或改写各工作线契约。

## 来源优先级

1. 用户明确确认的业务规则及明确裁定，优先于所有旧文档、设计稿、代码默认值和历史任务卡。
2. 专项契约/已验收需求文档只在其明确范围内有效；实施卡、设计和测试证据不得扩大业务授权。
3. 实现、测试、审查、部署记录分别证明相应事实。文档批准、设计批准、测试通过均不自动证明集成或上线。
4. 有冲突时保留冲突并列入待决，不从代码行为推定业务批准。
5. 来源不足、其他聊天不可见或附件缺失时明确标为缺件，不补猜。

## 状态口径

每条需求的确认、实现、验收、集成、上线分别记录。确认状态使用：**已确认、待确认、建议功能、暂缓/取消/被替代、来源不足**。实现状态使用：**已实现、部分实现、未实现、未知**；验收、集成和上线独立记为是/否/部分/未知，并给证据。此入口提交本身只整理文档，不授权开发。

## 范围与边界

已检查远端全部分支引用（非仅 `main`），包括租赁、合同、人脸门禁、数据库、管理后台、发布与运维资料。完整需求并非一个已存在的单一原始 PRD；部分旧设计图只作为界面线索。其他会话中的聊天、未提供的附件、供应商工作线原文无法从仓库验证，见待决清单。
