## P0 阻断

### 1. `FaceAccessContext` 实现错误，方法仍不是双参数签名

冻结 context 必须逐字段为：

```text
actorId
actorType = user | system | agent
orgId
permissions: Set<string>
idempotencyKey: 16–128位 [A-Za-z0-9._:-]
executionMode = demo | test | live
```

当前代码却把 `deviceId/grantId/validFrom/validUntil` 定义为 context，并继续使用 `enrollFace(input)` 单参数。必须改为 `enrollFace(input, context)`、`updateFace(input, context)`、`revokeFace(input, context)`、`queryOperation(input, context)`、`verifyEvent(input, context)`。

业务字段归 input：enroll 使用 `personId/deviceId/grantId/sourceFileId/validFrom/validUntil`；update 使用 `credentialId` 和已批准变更；revoke 使用 `grantId/credentialId`；query 使用 `jobId`；event 使用最小事件字段。`opId/requestDigest` 由服务端依据 context 和规范化 input 派生，不得作为客户端自由输入替代 context。

### 2. Mock 仍未要求显式选择

`provider = "mock"` 默认值意味着只传 mode 即启用 Mock。必须要求调用者同时显式传 `mode=demo|test` 和 `provider=mock`；缺任一项、live+mock、未知组合均 `NOT_CONFIGURED`。

### 3. `deviceEffective` 仍可关联错误 job

最新 job 仍只按 `credentialId` 过滤，可能选中另一设备或另一 grant 的任务。必须同时匹配 `orgId/deviceId/grantId/credentialId`，并核对 evidence 的 operation/action、受信来源及 `evidenceScope=device_verified`。不能由普通调用者仅传 `{trusted:true}` 建立真实生效证据。

### 4. 事件仍不满足最小合成事件契约

当前只判断签名非空，随后原样返回 payload；同 eventId 不同内容也会静默重放首个结果。M1 Mock 必须校验固定测试域、eventId、目标 job/device、递增版本、时间窗和 Mock 签名，保存事件摘要；同 ID 同摘要可重放，同 ID 不同摘要冲突。返回只含 `matchedJobId/action` 或 `rejected`，不得回显原始 payload。live event 一律 `NOT_CONFIGURED`。

## P1 必修

1. `publicReviewItem.evidenceScope` 不能写 `review/private`；冻结值是 `simulated/device_verified`。review/private 是读取权限范围，不是证据范围。
2. Q01 的 `displayState` 是 grant/job 投影，当前仅按 review/image 投影并不等价。应提供独立 access DTO：`grantState + jobState + displayState + evidenceScope + cleanupPending`。
3. `queryOperation` 输出应包含 `jobId/state/attempts/lastSuccessAt/failureReason(脱敏)`，不返回 opId 或摘要。
4. `sending` 后结果不明不能转 cancelled；取消只允许 queued。发送后无法证明未执行应进入 awaiting_result。
5. `jobId = opId` 的回退不可作为契约；jobId 和 operation key 是不同持久对象。
6. 文档中的“三轴”统一改为“四轴”，避免再次混淆审核、质量、grant 和 job。
