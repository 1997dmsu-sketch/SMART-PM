# DB-01：迁移、验证与回滚方案

状态：方案，无迁移脚本、无线上执行。基线为beta.16。默认本地演练；真实环境盘点需要届时的只读配置。本轮不运行 dbInit、不读取凭据、不调整门锁权限。

## 1. 阶段与开关

1. **设计收口**：确认CURRENT-STATE中Q01/Q02已收口，解决Q03–Q07或明确不开放的功能；DB-01文件与任务卡统一。
2. **只读演练**：从明确来源的脱敏副本生成报告、映射建议和冲突清单。默认不写库。
3. **基础设施探针**：隔离云环境验证事务竞争、固定ID占位、索引与安全规则；确认SDK版本及限额，形成实际运行报告。
4. **增量建模**：经审阅的manifest指定组织及记录映射，只添加新字段/集合；不改旧主键，不将旧绑定当成实名或主租客事实。
5. **影子比对**：旧读路径仍运行，新关系用于差异报告，不授予额外设备权限。控制台显示“待确认旧绑定”。
6. **冻结与对账**：短暂停止目标组织的身份/绑定/物业变更，封闭全部旧写入路径，处理最后增量。先单组织切换；不同组织可分别停留legacy/v2，不在同一组织混写。
7. **切换并观察**：identityMode、occupancyMode、fileMode按版本记录切换，相关读写必须配套；门锁另设设备权限切换里程碑，本轮不启用。

切换期间不能让phoneLogin/login/houseAdmin与新关系服务同时独立写权威数据。若需投影users.houses，只能由新服务单向生成，并附projectionVersion；已切换读权限不得再依赖可能滞后的投影。

## 2. 盘点与人工映射

| 来源 | 只读检查 | 处理方式 |
|---|---|---|
| users | 重复手机号、重复OPENID、空手机号、disabled状态、字段格式 | 不自动合并；保留所有_id，冲突组阻止身份切换 |
| 无账号居住人员 | 旧库无可靠人员档案来源 | 不根据姓名/手机号猜测账号；由管理员/主租客建person及实名申请，使用脱敏演练数据 |
| users.houses / owners.houses | 房产号是否存在、多个用户绑定同房、housesManaged差异 | 生成legacy_binding_review候选记录；无主租客角色、无有效期、无实名结论 |
| rooms | houseId重复、孤立floorId/layoutId、跨楼栋户型、重复房号、slots差异 | 保留_id和houseId；人工修复关联，不能按名称相近猜测 |
| property_catalog | parentId不存在、kind错配、重复code/level、组织来源不明 | 单组织来源经manifest确认后回填orgId；异常隔离 |
| houses | 双向关联不一致、无房间关联、公共标记不一致 | 已有正确关系保留；独立房源继续存在，不强行建房间 |
| accounts.json | 后台账号与管理组织授权 | 独立备份文件；显式org_membership映射，不导入users.role当组织管理员 |
| devices及其他设备集合 | houseId是否唯一可解析、公共设备语义 | 输出兼容风险，不变更设备、不执行开锁测试 |
| content/图片/vrFile | 本地/云URL、文件可用性、归属和用途 | 建文件记录及旧URL映射；缺失文件报告，不静默替换 |

身份证等真实资料不进入Git或可公开报告。生产演练统计可只包含记录ID、计数及脱敏值；冲突证据应在受限报告中保存。

## 3. 建议脚本接口（后续DB-08实现）

```text
node scripts/db-v2-migrate.mjs --dry-run --source <隔离配置别名> --manifest <审阅文件> --report <受限目录>
node scripts/db-v2-migrate.mjs --apply --manifest <相同文件> --expected-source-version <版本>
```

以上命令仅是目标接口，目前不存在，不可复制执行。不得默认生产环境。manifest包含migrationId、基线提交、组织映射、源快照校验、人工冲突决定及预期计数。

每条迁移任务使用确定性 migrationId+collection+recordId；记录beforeRevision/afterRevision、前镜像校验和、状态、错误。重复执行相同manifest无重复记录；源版本变化时停止该条并报告，不覆盖新业务。

文件只登记引用，物理搬迁后续独立校验checksum和可读性，再切引用；禁止先删除原件。附件移除与文件删除分离。

## 4. 备份与回滚

- 迁移前分别备份云集合、组织配置/开关、后台accounts.json、本地.data、文件清单及实际文件；备份密钥另行管理，不写进manifest。
- 在副本上完成恢复验证，光有“导出成功”不算恢复可用。
- 未切换时可撤销本次新增集合记录及本次新增字段，但必须匹配migrationId及afterRevision；已被业务修改的记录进入冲突处理。
- 切换后有新实名/关系/名单记录时，不可直接恢复旧快照，否则会丢失新审核或扩大权限。先暂停相关写入，按操作日志对账，保留新历史，再决定前滚修复或受控回退。
- 回退不得重新启用绕过组织/实名检查的旧bind接口；设备权限不随数据库回滚自动扩大。
- 回滚记录本身也审计；禁止删审核历史以“恢复干净”。

## 6. 分工与交付门槛

- DB-01：本轮四份文档，设计状态为待评审，不执行DB-02。
- DB-02/03：先实施基础组织/身份服务及云探针；失败不继续切换。
- DB-04/06：人工审核与名单，避免共改用户核心字段；接口契约统一后可以分支交付。
- DB-05：依赖以上服务、已确认Q01/Q02及Q05决定，最后连接关系激活。
- DB-07：独立文件适配；不接真实NAS，不重写VR产品功能。
- DB-08：非作者评审、隔离环境验收与演练报告；合并/上线单独安排。

不要求多模型重复实现。每次交接提供基线提交、任务卡、这四份文档、实际diff及已执行检查。未经评审的新设计不得当作已经上线的系统状态。
