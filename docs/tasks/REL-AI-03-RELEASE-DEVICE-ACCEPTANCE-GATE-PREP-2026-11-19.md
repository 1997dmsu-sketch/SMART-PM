## 1. 分层模型：六类环境，互不替代

| 层 | 代号 | 定义 | 可接受的证据 | 明确不能替代 |
|---|---|---|---|---|
| 模拟 | **S** | Mock Provider、demo 数据、LocalStore | 单元 / 契约测试输出（含全库零写断言） | 不能替代离线、真实云、真机、设备 |
| 离线 | **O** | 本地构建、静态检查、来源哈希、离线门禁 | 命令退出码 + 输出 + 提交 SHA | 不能替代真实云运行态与真机 UI |
| 真实云只读 | **C** | 受控测试云环境上的只读核对（如云函数存在性） | 只读列表 / 查询结果（脱敏、含时间与环境代号） | 不能替代真机 UI，也不能证明设备能力 |
| 真机 | **D** | 授权测试账号 + 真实手机 + 体验版 / 预览版 | 脱敏截图 / 录屏 + 设备型号 + 系统 + 微信版本 + 采集时间 | 不能替代真实云写、设备写、支付 |
| 支付 | **P** | 微信支付 / 预授权 / 退款 / 对账 | 支付流水号（脱敏）+ 时间 + 金额 + 状态机证据 | 独立门禁；任何 D 层通过都不覆盖 P |
| 设备 | **H** | 海康 `DS-K1T671BM` 实验室设备（隔离网络） | `HK-AI-06B` 证据模板（脱敏字段 + 哈希 + 复核人） | 独立门禁；任何 C / D 层通过都不覆盖 H |

### 1.1 硬规则

1. **一层一判**：每层独立给出 `PASS / FAIL / BLOCKED / not_requested`，不得合并成「整体通过」。
2. **禁止跨层外推**：`S` 层测试全通过不等于 `C`、`D`、`P`、`H` 任何一项通过；`C` 层只读通过不等于 `D` 层 UI 通过。
3. **禁止拼凑**：不同层、不同日期、不同设备/版本、不同账号的证据不得拼成一条验收结论。
4. **代码级证据与真机证据严格分离**：沿用 `REL-AI-01C` §0 口径，代码级 / 构建级证据**不构成**真机 UI 冒烟任何一项通过。
5. **默认关闭**：`allowDeviceOperations=false`、`providerReleaseApproved=false`、`eventTrustApproved=false` 在全部层保持，直到对应层单独批准。

## 2. 证据分级与采纳规则

| 等级 | 形式 | 是否可作为门禁依据 | 备注 |
|---|---|---|---|
| **E0** | 口头说明、聊天记录、会议纪要、未签字的「已恢复 / 已通过」 | **否** | 明确的「不沿用口头恢复」规则 |

| **E2** | 仓库内可复核文档 / JSON / 测试代码 | 是（需可定位） | 必须给 `分支@提交:路径` 与 blob SHA |
| **E3** | 平台 / 真机证据（截图、录屏、平台版本页、支付流水） | 是（需脱敏） | 必须附采集时间、设备/系统/微信版本、脱敏说明、文件哈希 |

### 2.1 采纳规则

1. 本卡只采纳 **E2 / E3**；E1 只能用于环境自证（如本会话的 pwd / HEAD），不能用于业务验收。
2. 任何「已恢复」「已验收」「可上线」表述若无 E2 / E3，一律记为 **未验证**，不进入结论。
3. E3 证据必须脱敏：不得含完整 AppID、云环境 ID、完整 IP / MAC / 序列号、账号密码、Token、Cookie、openid、手机号、真实人脸、真实住户资料。
4. 证据一旦无法脱敏，即 **不采集 / 不提交**；不得「先记下来再处理」。
5. 同一事实若只有 E0，结论写「未知」，并进入证据缺口表。

**既有裁定边界**：以上分级用于本次发布证据采纳，不撤销调度方已书面确认且要求继承的 G4 裁定。裁定状态与原评审副本的可访问性分别记录；继承裁定不等于本轮重验或 PG-03 发布证据已齐。

## 6. 失败停止矩阵（Fail-Stop）

> 任一条件触发即停止；**停止不需要审批**。先保证人身 / 设备 / 数据安全，再记录证据。

| ID | 触发条件 | 立即动作 | 恢复条件（需书面批准） | 禁止的「掩盖」手段 |
|---|---|---|---|---|
| F-01 | SHA / 标签 / 版本号 / 制品 SHA-256 任一不一致 | 停止；保留现场；不重打制品 | 发布指挥 + Codex 重新冻结 | 改标签、重打 ZIP 冒充原包、就地修复 |
| F-02 | `allowDeviceOperations` 不为 `false`，或 runtime 非预期模式 | 立即停止；不点击开门 | 配置快照恢复 + 复核 | 临时打开设备写「验证一下」 |
| F-03 | 出现真实设备写、未知域名、未知云函数、未批准 HTTP 调用 | 立即断开；记录脱敏证据 | 安全 / 云管理员书面说明 + 重新审批 | 忽略日志、关闭抓包、删除记录 |
| F-04 | 无授权测试账号 / 无真机 / 无微信版本 | 停止真机部分，整体记 `BLOCKED` | 指定授权人员并完成本人登录 | 用开发者工具模拟器冒充真机 |
| F-05 | 任一项冒烟 FAIL 或结果不确定 | 停止后续项；保存证据；不开返工卡前不重试 | 修复 + 重新执行全部受影响项 | 把 FAIL 改写成 BLOCKED / PASS |
| F-06 | 证据无法脱敏或已发生敏感泄露 | 停止；隔离 / 删除不安全副本；按事件上报 | 安全复核 + 扫描零命中 | 直接提交原图、原日志、原抓包 |
| F-07 | 回滚锚点缺失或不可执行 | 不进入发布审批 | 补齐锚点 + 回滚演练通过 | 用「到时候再说」代替锚点 |
| F-08 | 平台版本列表 / 上一体验版信息无法核对 | 停止；不声称可回退 | 授权人员人工补录 | 编造版本号 / 时间 |
| F-09 | 出现真实人员、真实人脸、真实住户数据 | 立即停止；隔离；按隐私事件处理 | 隐私负责人批准 + 仅合成数据 | 「只测一次」 |
| F-10 | 需要生产管理员凭据 / 共享账号 / 默认密码 | 不登录、不猜密码 | 专用实验室账号 + 书面批准 | 借用他人账号 |
| F-11 | 支付异常（重复扣款、金额不符、回调丢失） | 停止支付场景；保留流水 | 支付负责人 + 财务对账 | 手工改订单状态 |
| F-12 | 环境 / 网络隔离不成立（生产上联、生产 DNS、生产 VLAN） | 立即断开；不抓生产流量 | 网络负责人书面隔离证明 | 继续测试并「注意点」 |
| F-13 | 证据包缺少时间 / 设备 / 版本 / 哈希任一要素 | 该证据判无效，重采 | 按 §2 补齐 | 事后补时间、补哈希 |
| F-14 | 发现未审批的并行 / 超范围操作 | 立即停止；撤销审批；断开 | 重新审批 + 重新基线 | 事后追认 |

### 6.1 停止后的通用处置

1. 先急停 / 断电 / 断网（按风险），再记录。
2. 保留脱敏证据：时间、环境代号、版本 SHA、触发条件、已执行步骤、截图 / 日志哈希。
3. 不删除原始证据（除非含未脱敏敏感值；此时按 F-06 隔离并记录）。
4. 通知发布指挥、见证人、对应安全 / 隐私 / 设备角色；相关设备贴「隔离封存」。
5. 未完成根因分析、未重新基线、未重新审批，不得恢复。
6. 每次停止都写入证据包，复审时说明「为什么停、停了多久、如何恢复」。
