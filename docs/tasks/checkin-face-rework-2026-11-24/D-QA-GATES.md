# D：独立贯穿 QA、静态门禁与来源校验

先读 README、COMMON 和固定复审全文。本路负责 R10、C1 与跨模块独立验证；不编辑 A/B/C 所拥有的生产或既有测试文件。

## 必做

1. R10 的 mode=device 与 validityMode=fixed 分别/全部检查，任一缺失都失败；不能注释命中即证明实际请求正确。分别移除一项的负控必须精确失败。
2. C1 使用专门新文件哈希清单，不伪造旧 originalSha256。新增实际读取清单的校验入口并接到候选发布检查，核验路径唯一/合法、实际哈希、新云目录和本地导入闭包覆盖。保留原来源校验职责。
3. **A/B/C全停编辑后**统一更新来源清单并复算；中途可开发校验器但不得抢写清单。新增文件/锁文件按真实用途登记，不能只更新旧10条却遗漏新的云执行代码。
4. 新增独立跨模块回归：SDK形状 fileID 同一值贯穿上传→创建任务→worker下载；真实WXML结构配套；分离base/tx与回滚；创建/领取交错；漏设备key；下载后过期/撤权；默认依赖解析；照片处理/失败结果；普通账号不误报成功。oracle来自冻结契约，不调用同一个生产helper计算“期望值”。
5. 每项先证明当前固定候选为何失败/缺覆盖，再在修复后验证；禁用关键修复的受控副本应命中对应断言。探针退出0不等于旧候选通过，语法错误/依赖缺失不计业务反证。
